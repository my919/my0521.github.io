Spring Boot 入门：环境、骨架与启动

发表于 2026-05-01 更新于 2026-05-04 分类于 SpringBoot 本文字数： 1.1k 阅读时长 ≈ 4 分钟

Spring Boot 在 Spring Framework 之上提供约定优于配置的起步依赖、内嵌 Servlet 容器与生产级运维钩子，用少量配置即可跑起 Web、数据访问、消息 等能力。下文从官方文档入口、环境、创建第一个应用、主类与配置到常用延伸，按步骤写清楚；与 Spring Cloud 同栈的 BOM 与 Gradle 细节见站内 Spring Cloud Alibaba 与 Gradle 从零搭建，Gradle 安装与镜像见 source/_posts/Java/gradle.md（《Gradle 构建工具》）。

一、官网与文档

  • Spring Boot 项目页：https://spring.io/projects/spring-boot
  • 参考手册（当前稳定版）：https://docs.spring.io/spring-boot/reference/
  • Spring Initializr（在线生成工程）：https://start.spring.io/
  • Spring Guides：https://spring.io/guides

版本线简述：Spring Boot 3.5.x 为 3.x 长期支持线之一；Spring Boot 4.0.x 与 Spring Framework 7、Spring Cloud 2025.1.x 同世代，站内 SCA 2025.1.x 示例采用 Boot 4.0.x。新建工程前请到 Spring Boot 发行说明核对与你所选 JDK、依赖的兼容性。

二、环境准备

1. JDK

Spring Boot 3.x / 4.x 要求 Java 17 及以上（部分组件推荐 21）。终端验证：

2. IDE（可选但推荐）

IntelliJ IDEA、VS Code（Extension Pack for Java）、Eclipse 均可；下文以「能打开 Maven / Gradle 工程并运行 main」为前提。

3. 构建工具

  • Maven：多数示例以 pom.xml 展示依赖；本机需能执行 mvn。
  • Gradle：推荐 Kotlin DSL（build.gradle.kts）；安装、Wrapper 与国内镜像见 source/_posts/Java/gradle.md。

三、创建第一个 Spring Boot 应用

1. Spring Initializr（最快）

  1. 打开 https://start.spring.io/
  2. Project 选 Maven 或 Gradle；Language 选 Java；Spring Boot 选稳定版（与上节版本线一致）。
  3. Group / Artifact 按规范填写（如 com.example / demo）。
  4. Dependencies 至少勾选 Spring Web（若要健康检查再加 Spring Boot Actuator）。
  5. 点击 Generate，解压后用 IDE 打开根目录（含 pom.xml 或 build.gradle.kts 的目录）。

2. IntelliJ IDEA 向导

File → New → Project 中选择 Spring Initializr（或 New Project 中带 Spring Boot 的向导，视 IDEA 版本而定），与网页版 Initializr 等价：选 JDK、Boot 版本与依赖后生成工程。

3. 与手写构建脚本的关系

Initializr 生成的是可编译骨架；若需叠加 Spring Cloud Alibaba 等 BOM，往往要在 pom.xml / build.gradle.kts 中手工补充 dependencyManagement 与依赖坐标，与 Spring Cloud Alibaba 与 Gradle 从零搭建 一文中的写法一致，不要假设向导已包含 Cloud。

五、常用能力与延伸

1. Actuator 与 Profile

  • Actuator：依赖 spring-boot-starter-actuator，暴露 /actuator/health 等端点；生产务必限制暴露面并加鉴权。
  • Profile：用 spring.profiles.active 区分 dev / prod，配合 application-dev.yaml 等多文件配置。

2. 与 Spring Cloud 的关系

Spring Boot 解决「单应用如何快速装配与运行」；Spring Cloud 在 Boot 之上提供注册发现、配置中心、网关等分布式系统能力。微服务路线在掌握 Boot 后，可按 Spring Cloud Alibaba 与 Gradle 从零搭建 引入 BOM 与 Nacos 等组件。

3. 容器化与部署

Boot 应用通常打包为 jar（java -jar 运行）或制作为容器镜像；与 Docker、Kubernetes 相关的端口、探针、JVM 参数需与 server.port、Actuator 路径一并规划，详见 Spring Boot 文档中 Deployment、Container Images 等章节。

Node的nvm工具

发表于 2026-04-30 分类于 Node 本文字数： 856 阅读时长 ≈ 3 分钟

nvm（Node Version Manager）是用于在同一台机器上安装、切换多份 Node.js 的 Shell 脚本工具，适合不同项目依赖不同 Node 版本时使用。下面按安装 nvm、安装并固定 Node v22.22.2、项目级版本、常用命令说明；macOS / Linux 以官方 nvm-sh/nvm 为准，Windows 见文末补充。

一、nvm 是什么

  • 作用：从源码或官方预编译包拉取 Node，把各版本隔离在用户目录下，通过 nvm use 切换当前终端使用的 node / npm。
  • 与全局安装的区别：不会把某个 Node 强行装进系统目录；切换版本只影响当前 Shell（及子进程）。
  • 本文示例版本：统一以 Node v22.22.2（Current/LTS 以你安装时官方为准）演示命令。

五、Windows 与补充说明

  • 经典 nvm（nvm-sh）不支持原生 Windows。若在 Windows 上开发，常见做法有：
    1. 使用 nvm-windows（命令与 nvm-sh 接近但不完全相同，安装包在 Releases 下载）；
    2. 使用 WSL，在 Linux 子系统里按本文 二、三 安装 nvm-sh；
    3. 使用 fnm、Volta 等跨平台工具（非 nvm，但可管理多版本 Node）。
  • 国内镜像：可在安装 Node 前设置 NVM_NODEJS_ORG_MIRROR（具体变量名与地址以当前 nvm 文档为准），以加速 nvm install。
  • 与系统自带 node 冲突：若曾用包管理器安装过 node，which node 可能仍指向旧路径；确保 nvm use 后 PATH 中 nvm 的 shim 在前，或卸载系统级 Node 后再试。
