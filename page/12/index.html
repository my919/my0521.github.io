第二章：Docker 部署 ClickHouse 实践

概念基础

  1. 为什么用容器跑 ClickHouse：一条命令拉起、版本随标签固定、环境与宿主机解耦——本地分析环境与生产部署的基础单元。
  2. 数据持久化是底线：必须把数据目录 /var/lib/clickhouse 挂载到命名卷或宿主机目录，否则容器删除即数据清零。

第二章：Docker 部署 PostgreSQL 实践

概念基础

  1. PostgreSQL 是 C/S 架构的关系库：服务端 postgres 进程监听 5432 端口，客户端（psql、JDBC）通过连接串访问；「部署」的本质就是两件事——把服务端进程跑起来、让数据落在可靠的地方。
  2. 容器化 = 环境即代码：镜像内置二进制与依赖，一条命令起库；POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB 环境变量完成初始化，首次空数据目录时还会自动执行 /docker-entrypoint-initdb.d 下的脚本。
  3. 三种部署形态由小到大：docker run 单容器（本地开发）→ Docker Compose 编排（健康检查、.env 管敏感项）→ Kubernetes（探针、PVC 持久化、集群化运维）。
  4. 数据与容器分离：容器随时可删，数据必须在**卷（Volume）**上——镜像升级换容器、卷不动，这是容器化数据库的第一原则。

第五章：系统运维进阶

概念基础

  1. SSH 是远程运维的生命线：服务器只在机房里亮灯，日常工作全靠 ssh 进入；密钥免密、~/.ssh/config 别名、端口转发是三件必修装备。
  2. systemd 是 PID 1：现代 Linux 的 1 号进程，统一管理服务、日志（journald）、定时任务（timer）——把自己的脚本注册成服务，才算真正「上线」。
  3. 日志先行：排障顺序永远是「先看日志，再猜原因」；journalctl 统一了服务的 stdout 与系统日志，带 --since、-f、-p err 精确定位。
  4. 资源要主动观测：磁盘（df/du）、内存（free）、文件句柄（lsof）、进程（top/ps）是容量与故障预警的四个仪表盘。
  5. 重复的事交给调度器：临时脚本用 cron，需要依赖关系、日志、错峰的服务级调度用 systemd timer。

第四章：文本处理三剑客与管道

概念基础

  1. 管道是 Unix 的组合器：每个工具只做一件事（grep 找行、sed 改流、awk 切列），用 | 把小工具拼成大数据流水线——这是 shell 至今未被完全取代的核心原因。
  2. grep = 过滤：按模式从文本中筛出符合条件的行，定位问题第一工具。
  3. sed = 流编辑：逐行读入、按脚本替换/删除/打印，批量改配置文件的首选。
  4. awk = 按列编程：把每行按分隔符切成字段，可做条件过滤、统计、格式化输出，接近一门微型语言。
  5. 正则是通用货币：三剑客的正则语法略有差异（grep -E / sed -E / awk 用 ERE），记熟 ^ $ . [] [^] * + ? () | {n,m} 就能覆盖 90% 场景。

第二章：Windows 上 WSL（Rocky Linux）与 Docker Desktop

概念基础

  1. WSL 是什么：WSL（Windows Subsystem for Linux）让 Windows 直接运行真正的 Linux 发行版，无需双系统或整机虚拟机，一条命令即可进出 Linux 环境。
  2. WSL2 的意义：WSL2 基于轻量级虚拟机，系统调用兼容性完整，是 Docker Desktop 官方推荐的运行后端——没有 WSL2 就没有流畅的容器体验。
  3. 为什么选 Rocky Linux：与 RHEL 同源的企业级发行版，dnf 生态与生产服务器一致，作为本地演练环境最贴近真实运维。
  4. Docker Desktop 的角色：提供图形化引擎管理（更新、证书、镜像加速），通过 WSL integration 把 docker CLI 注入各发行版，Rocky 内无需再装 dockerd。
  5. 适用场景：在 Windows 机器上做 Linux 运维演练与容器开发；代码放在发行版内的 Linux 文件系统中可获得最佳 I/O 性能。
