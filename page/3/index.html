Docker 部署 1Panel

发表于 2026-05-02 更新于 2026-05-03 分类于 Cloud 本文字数： 1.5k 阅读时长 ≈ 5 分钟

在已安装 Docker 的环境中，可用 docker run 拉起 1Panel V2（社区镜像 moelin/1panel，非 FIT2CLOUD 官方安装包；升级路径与支持策略与官方宿主版可能不同）。镜像说明、标签与环境变量以 Docker Hub：moelin/1panel 为准；生产请固定小版本标签（如 moelin/1panel:v2.0.6），勿盲目追 latest。官方在线安装见：在线安装。

部署按宿主机与引擎分两类，下文分开写，勿混用 --network host 与 -p：

  1. Windows + Docker Desktop + WSL：在 WSL（如 Rocky Linux 10 等发行版）或 Windows CMD 里执行 docker run，引擎为 Docker Desktop 时须用端口映射。
  2. Linux Docker 主机：云服务器、物理机或虚拟机内原生 Docker Engine，可用 --network host。

共用前提

  • docker version 客户端与 Server 均正常，能拉取 Docker Hub（或已配置镜像加速）。
  • 建议内存 ≥ 1GB；多架构以 Hub 页为准。
  • 将 PASSWORD、ENTRANCE 等换成自己的值；变量含义见文末 「常用环境变量」。

第一类：Windows + Docker Desktop + WSL

场景：宿主机为 Windows，容器由 Docker Desktop 提供引擎；你在 WSL 里打开终端（发行版可为 Rocky Linux 10、Ubuntu 等），docker version 的 Server 往往显示 Docker Desktop 或上下文为 desktop-linux。此时容器里的 host 网络与你在 WSL 里访问的 localhost 不是同一概念，不要使用 --network host，应使用 -p <PORT>:<PORT>。

若曾误用 host 建过同名容器，先 docker rm -f 1panel-v2 再按本节重建。

Windows CMD（行末 ^ 续行）

^ 须为行末最后一个字符（后无空格），末行不写 ^。-e 的值在 CMD 里用双引号较稳妥。

卷说明（与 Linux 类一致，路径在 Docker Desktop 下仍写 /var/run/docker.sock、/opt，由 Desktop 映射到引擎；异常时以当前 Desktop 文档为准。若 -v 与 WSL2 / Linux 容器 后端要求不符，按 Docker Desktop 文档调整。）

浏览器访问（本机）

多数情况：http://127.0.0.1:10086/<ENTRANCE>（与示例 ENTRANCE 一致时）。在 WSL 内若 localhost 仍不通，可试 http://$(grep -m1 '^nameserver' /etc/resolv.conf | awk '{print $2}'):10086/<ENTRANCE>（常为 WSL2 下可达的 Windows 主机 IP，以本机为准）。

可选：docker compose（端口映射）

在同目录执行 docker compose up -d。

第二类：Linux Docker 主机

场景：Linux 云服务器、物理机或虚拟机内安装 Docker Engine（非 Docker Desktop 作为服务端）。可用 --network host，面板监听端口即宿主机端口，与安全组、防火墙规则一致。

多行 docker run（--network host）

-v /var/run/docker.sock：面板管理宿主机 Docker。
-v /opt:/opt 与 BASE_DIR=/opt：数据目录可改，须与挂载路径同步。
moelin/1panel:v2：跟踪 V2 最新构建；生产建议改为 Hub 具体版本号。

可选：docker compose（host 网络）

将下文保存为同目录下的 compose.yaml 或 docker-compose.yml。

在同目录执行 docker compose up -d。

组件 说明 常见映射端口（示例）

3. 与官方「Broker + Proxy」快速入门的关系

Apache 文档推荐挂载 broker.conf 并执行 mqbroker --enable-proxy（见 Run RocketMQ in Docker）。下文 Compose 提供带 Proxy 的完整示例；若仅需经典 Remoting 客户端，可将 Broker 的 command 改为 sh mqbroker -n <namesrv>:9876 并去掉 Proxy 相关端口（需自行验证与客户端版本匹配）。

4. 资源与持久化

Broker 磁盘与堆内存占用随主题、队列与流量增长较快；Compose 与 K8s 中为 Broker 数据目录挂载卷，并酌情提高 limits。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式跑 Apache RocketMQ，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 RocketMQ 一键部署：由面板编排 NameServer、Broker（及上架版本若含的 Proxy）与数据卷、端口。与下文 docker / Compose / K8s** 中的 **broker.conf**、**NAMESRV_ADDR**、**brokerIP1` 与端口映射对齐或排障时，自 # 三 起各节仍可作对照。适合单台 VPS、家庭服务器等场景。

5. 镜像加速与构建缓存（Docker Engine）

在 Docker Desktop → Settings（设置）→ Docker Engine 中编辑 JSON（与引擎配置同源，保存后 Apply & restart 生效）。若已有其它键（如 insecure-registries），请把下面片段合并进现有对象，不要整段覆盖导致丢配置。

  • registry-mirrors：拉取镜像时优先走列表中的镜像站，减轻访问 docker.io 的延迟与失败（镜像站可用性与合规以你网络环境为准，可日后替换为团队提供的地址）。
  • builder.gc：为 BuildKit 构建缓存开启自动回收，defaultKeepStorage 限制默认保留量（示例 20GB），避免构建缓存占满磁盘。

修改后点击 Apply & restart；再在 Rocky 或 PowerShell 中执行 docker info，在输出里确认 Registry Mirrors 已包含上述地址。

6. 文件与性能建议

  • 项目代码放在 WSL 发行版自己的 Linux 文件系统里（例如在 wsl -d Rocky-10 里用 ~/project，即 /home/你的用户/project），不要放在 /mnt/c/... 下做大量编译与 Docker 构建，可减少跨系统 I/O 延迟。

  • Docker Desktop 的 Settings → Resources 可调 CPU、内存、磁盘镜像上限，与 Rocky 其它进程共用本机资源，按机器配置酌情调大。
