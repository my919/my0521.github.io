概述

本文档描述仓库 sql/init.sql 中的 MySQL 8+ 库表设计，覆盖以下业务模块：

模块 表
字典 sys_dict_type、sys_dict_data

共 16 张表，引擎均为 InnoDB，字符集 utf8mb4。

设计约定

约定 说明
无外键 表间通过业务字段（如 user_id、role_id）关联，便于分库分表与数据迁移
逻辑删除 业务表含 deleted（0 否 / 1 是），查询需带 deleted = 0；组合索引常含 deleted
审计字段 多数业务表含 create_time、update_time（自动维护）
树形结构 sys_dept、sys_menu、common_category 使用 parent_id + ancestors（祖级 ID 路径，如 1,2,3）
关联表 sys_user_role、sys_role_menu 无 deleted，用唯一键防重复

常见问题

脚本执行后表已存在

init.sql 对每张表先 DROP TABLE IF EXISTS 再 CREATE，会清空该表数据。生产环境请勿直接全量执行，应使用迁移工具（Flyway/Liquibase）做增量变更。

逻辑删除查询不到数据

MyBatis-Flex 或业务层需统一过滤 deleted = 0；关联表 sys_user_role 等无 deleted，删除关系应物理 DELETE。

订单与商品库存

当前 DDL 未包含库存扣减、支付流水表；goods.stock / goods_sku.sku_stock 需在业务代码中维护一致性。

SpringBoot集成MyBatis-Flex与多数据源

发表于 2026-05-16 分类于 SpringBoot 本文字数： 712 阅读时长 ≈ 2 分钟

概述

  • MyBatis-Flex：轻量 ORM，提供 IService / ServiceImpl 与分页。
  • dynamic-datasource：运行时切换多数据源（本项目：MySQL + PostgreSQL）。

MyBatis-Flex 与 MyBatis-Plus 对比

二者都是在 MyBatis 之上的增强框架，分层模型相近（BaseMapper → IService → ServiceImpl），CRUD 与分页 API 名称大多一致，迁移成本较低。主要差异如下。

维度 MyBatis-Flex MyBatis-Plus
定位 轻量、低侵入，强调查询性能与 APT 编译期能力 生态成熟、文档与社区体量大
核心包 com.mybatisflex com.baomidou.mybatisplus
Mapper BaseMapper<T> BaseMapper<T>
Service IService / ServiceImpl IService / ServiceImpl
条件构造 QueryWrapper、QueryChain（链式） QueryWrapper、LambdaQueryWrapper
分页 Page<T>（Page.of(pageNumber, pageSize)） Page<T>（new Page<>(current, size)）
实体表映射 @Table、APT 生成 *TableDef 类型安全列名 @TableName、@TableField 等
代码生成 MyBatis-Flex Codegen MyBatis-Plus Generator
多数据源 常与 dynamic-datasource（Baomidou）搭配，注解 @DS 同上，同一套 dynamic-datasource
Spring Boot 4 mybatis-flex-spring-boot4-starter（本项目使用） 需关注对应 starter 版本是否已支持 Boot 4

查询写法示例（语义等价）：

Flex 通过 APT 生成 SysUserTableDef，列名在编译期校验；Plus 更常用 Lambda 方法引用，运行时反射解析字段。

选型参考（与本模板相关）：

  • 已熟悉 Plus 且团队无迁移诉求：继续用 Plus 即可，多数据源仍可用 dynamic-datasource。
  • 希望依赖更轻、查询链路与 APT 表定义、或需要 Spring Boot 4 官方 starter：选 Flex（本仓库默认方案）。
  • 二者均不绑定特定数据库；本项目的 MySQL + PostgreSQL 切换由 dynamic-datasource 负责，与选 Flex 还是 Plus 无关。
