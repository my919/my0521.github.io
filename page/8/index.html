Linux

发表于 2026-05-01 更新于 2026-05-31 分类于 Linux 本文字数： 476 阅读时长 ≈ 2 分钟

Linux 是开源 Unix 系内核，常搭配 GNU 工具链构成各类发行版（RHEL/Rocky、Debian/Ubuntu、Arch 等），广泛用于服务器、容器宿主与开发环境。下面从「发行版与 Shell → 文件与权限 → 进程与服务 → 网络与防火墙 → 包管理与容器 → WSL 开发」顺序写清楚。

一、发行版与 Shell

系列 包管理 典型用途
RHEL / Rocky / Alma dnf/yum 企业服务器、K8s 节点
Debian / Ubuntu apt 云主机、桌面、CI
Arch pacman 滚动更新、开发者桌面

默认 Shell 多为 bash；脚本首行 #!/bin/bash，交互与运维命令在终端执行。

二、文件系统与权限

  • 根目录 /：/etc 配置、/var 可变数据、/home 用户家目录、/tmp 临时。
  • 软/硬链接：ln -s 与 ln。
  • 查找：find、grep（或 ripgrep）。

三、进程与服务

  • systemd：.service 单元管理守护进程。
  • cron / timer：定时任务。
  • ulimit：打开文件数、进程数限制（高并发服务需调优）。

四、网络

DNS、路由、iptables/nftables 排障是运维常见技能；协议细节见 TCP、HTTP。

五、包管理与容器

Docker 与 Kubernetes 多数运行在 Linux 内核特性（namespace、cgroup）之上。

六、WSL 与开发环境

Windows 上可用 WSL2 运行 Linux 发行版，与 Docker Desktop、VS Code Remote 配合。本站 WSL-Rocky 记录 Rocky Linux 子系统安装与注意点。

七、学习路径建议

  1. 熟练 Vim/nano、ssh、scp/rsync
  2. 理解 systemd、日志与磁盘（df/du/lsof）
  3. 会写 bash 脚本处理批量运维
  4. 结合 Nginx、数据库与中间件 Docker 文章做实战

LLM

发表于 2026-05-01 更新于 2026-05-31 分类于 AI 本文字数： 509 阅读时长 ≈ 2 分钟

大语言模型（Large Language Model，LLM） 是在海量文本上预训练的超大规模 Transformer，具备通用语言理解、推理与生成能力。下面从「预训练与对齐 → Prompt 与上下文 → RAG 与工具调用 → 微调方式 → 部署与评估 → 与 ML/DL 的关系」顺序写清楚。

RAG 检索增强流程



flowchart LR
  Q[用户问题] --> E[Embedding]
  E --> V[(向量库)]
  V --> Ctx[相关文档片段]
  Ctx --> LLM[LLM + Prompt]
  Q --> LLM
  LLM --> A[回答]

一、生命周期

阶段 说明
预训练 下一词预测（Causal LM）或掩码语言模型，学通用语言与知识
监督微调（SFT） 指令数据上对齐「助手」行为
RLHF / DPO 等 人类偏好或偏好对优化安全性与有用性
推理部署 量化、批处理、KV Cache、投机解码

代表模型族：GPT、Llama、Qwen、DeepSeek 等（以各开源/商用许可为准）。

二、Prompt 与上下文窗口

  • System / User / Assistant 角色消息构成对话。
  • Few-shot：在 Prompt 中给示例引导格式。
  • Context Window：模型一次可处理的 Token 上限；长文档需分块或 RAG。
  • Temperature / Top-p：控制采样随机性。

三、RAG 与 Agent

1. RAG（检索增强生成）

降低幻觉、接入私有知识；向量库可与 Redis 向量检索、专用 DB 配合。

2. 工具调用（Function Calling）

模型输出结构化 JSON 调用 API（查天气、查订单），由应用执行后把结果回传模型。

四、微调方式

方式 说明
全量微调 更新全部参数，成本高
LoRA / QLoRA 低秩适配器，省显存
继续预训练 领域语料增强行业知识

训练栈常基于 PyTorch + Hugging Face Transformers / PEFT。

五、评估与安全

  • 基准：MMLU、HumanEval（代码）等（仅作参考）。
  • 业务指标：任务成功率、人工抽检、延迟与成本。
  • 风险：幻觉、注入攻击、隐私泄漏；需权限控制、输出过滤与审计。

基础理论见 ML、DL。

DL

发表于 2026-05-01 更新于 2026-05-31 分类于 AI 本文字数： 447 阅读时长 ≈ 1 分钟

深度学习（Deep Learning，DL） 使用多层神经网络自动学习层次化特征，在视觉、语音、自然语言等领域取得突破。下面从「神经网络基础 → CNN / RNN / Transformer → 训练技巧 → 框架与硬件 → 与 LLM 的关系」顺序写清楚。

训练反向传播



flowchart LR
  X[输入] --> F[前向传播]
  F --> L[损失 Loss]
  L --> B[反向传播梯度]
  B --> U[更新权重]

一、神经网络基础

  • 前向传播：输入 → 各层线性变换 + 非线性激活（ReLU、GELU、Sigmoid）。
  • 损失函数：分类 Cross-Entropy、回归 MSE 等。
  • 反向传播：链式法则计算梯度，SGD/Adam 等优化器更新参数。

二、典型架构

架构 适用
MLP 表格、简单向量
CNN 图像、局部空间模式
RNN/LSTM/GRU 序列（较长依赖现多被 Transformer 补充）
Transformer NLP、多模态；Self-Attention 建模长距离依赖

ResNet、U-Net、BERT、GPT 等均建立在上述组件之上。

三、训练技巧

  • Batch Normalization / Layer Norm：稳定训练。
  • Dropout：减轻过拟合。
  • 学习率调度：Warmup、Cosine Decay。
  • 混合精度（AMP）：FP16/BF16 加速、省显存。
  • 梯度裁剪：RNN/大模型训练防爆炸。

数据：增强（随机裁剪、翻转）、归一化；划分训练/验证，早停（Early Stopping）。

四、框架与硬件

  • PyTorch：研究与应用主流（见 PyTorch）。
  • TensorFlow/JAX：生产与 TPU 生态。
  • GPU/CUDA：大规模训练依赖；推理可用 ONNX Runtime、TensorRT 等。

五、与 ML、LLM

  • 传统 ML：小数据、表格、可解释场景仍常用 GBDT。
  • DL：表示学习为主。
  • LLM：超大 Transformer 预训练 + 微调/对齐；视觉侧有 ViT、Diffusion 等并行发展。

计算机视觉入门可结合 OpenCV。

ML

发表于 2026-05-01 更新于 2026-05-31 分类于 AI 本文字数： 525 阅读时长 ≈ 2 分钟

机器学习（Machine Learning，ML） 让计算机从数据中学习规律，对新样本做预测或决策，而无需为每种情况手写规则。下面从「问题类型 → 典型流程 → 常用算法 → 评估与过拟合 → 与 DL/LLM 的关系」顺序写清楚。

典型流程



flowchart LR
  Raw[原始数据] --> Clean[清洗特征]
  Clean --> Train[训练模型]
  Train --> Eval[验证集评估]
  Eval --> Deploy[部署推理]

一、问题类型

类型 目标 示例
监督学习 有标签，学输入→输出映射 分类（垃圾邮件）、回归（房价）
无监督学习 无标签，发现结构 聚类、降维、异常检测
强化学习 智能体与环境交互最大化回报 游戏、机器人控制

二、典型流程

  1. 问题定义与指标（准确率、F1、AUC、RMSE 等）。
  2. 数据收集与清洗：缺失值、异常值、泄漏（train/test 混用未来信息）。
  3. 特征工程：数值缩放、类别编码、时间特征。
  4. 模型训练与验证：训练集 / 验证集 / 测试集或 K 折交叉验证。
  5. 部署与监控：数据漂移、模型退化、在线 A/B。

三、常用算法（概览）

  • 线性模型：逻辑回归、线性回归、SVM（核方法）。
  • 树模型：决策树、随机森林、GBDT、XGBoost/LightGBM（表格数据仍强）。
  • 距离方法：KNN。
  • 无监督：K-Means、PCA、t-SNE（可视化）。

四、过拟合与正则

  • 过拟合：训练集很好、泛化差 → 更多数据、简化模型、L1/L2 正则、Dropout（神经网络侧）。
  • 偏差-方差权衡：模型容量与数据量匹配。
  • 交叉验证：稳定估计泛化性能。

五、与 DL、LLM 的分工

层次 说明
传统 ML 表格、小数据、可解释性要求高
DL 图像、语音、复杂非线性表示
LLM 自然语言理解与生成；下游常 微调 或 RAG

深度学习框架见 PyTorch；Python 工程见 Python-UV。

Docker 用容器封装应用及其依赖，在隔离的命名空间与 cgroup 中运行，共享宿主机内核，实现「一次构建、到处运行」。下面从「镜像与容器 → 常用命令 → Dockerfile 要点 → 网络与卷 → Compose 与生产 → 与本站其它文章的关系」顺序写清楚。

一、核心概念

概念 说明
镜像（Image） 只读分层文件系统 + 元数据，由 Dockerfile 或 docker commit 构建
容器（Container） 镜像的可运行实例，可写层在容器生命周期内存在
仓库（Registry） Docker Hub、私有 Harbor 等，用于推送/拉取镜像
Docker Engine dockerd 守护进程 + **docker CLI

与虚拟机对比：容器不包含客户机 OS，启动快、密度高；隔离性弱于完整 VM，敏感多租户需额外加固。

Zigbee

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 337 阅读时长 ≈ 1 分钟

Zigbee 是基于 IEEE 802.15.4 的低功耗 mesh 物联网协议：2.4 GHz（亦有个别 sub-GHz），Coordinator + Router + End Device，应用配置文件如 Home Automation。下面从「网络层 → 设备类型 → ZCL 集群 → 与 Bluetooth/LoRaWAN 对照 → 开发栈」顺序写清楚。

Mesh 拓扑



flowchart TB
  C[Coordinator 协调器] --> R1[Router 路由]
  R1 --> R2[Router]
  R2 --> E1[End Device 传感器]
  R1 --> E2[End Device 开关]

一、802.15.4 基础

  • PHY/MAC：短帧、CSMA-CA、AES-128 链路加密。
  • Zigbee 在之上定义 NWK、APS、ZDO 与应用层 ZCL。

二、设备角色

角色 说明
Coordinator 建网、分配 PAN ID、短地址，通常 1 个
Router 中继、常供电
End Device 叶子节点，可 Sleep，通过父节点通信

Mesh 多跳扩展覆盖；路由表由 AODV 类机制维护（依栈实现）。

三、ZCL（Zigbee Cluster Library）

与 Bluetooth GATT 类似：标准化集群/属性/命令，保证互操作。

四、与其它无线

协议 特点
Zigbee 家居 mesh、中等数据率、低功耗
BLE Mesh 蓝牙生态、手机直连
LoRaWAN 公里级、星型、极低速率
Wi-Fi 高吞吐、功耗高

网关常把 Zigbee 转 MQTT / HTTP 上云。

五、开发与认证

  • 芯片：Silicon Labs、TI CC2652、NXP JN5169 等。
  • 栈：Zigbee PRO、Z3Gateway；开源 Z-Stack 部分版本。
  • Zigbee 认证：互操作 logo 需过联盟测试。

联盟：https://csa-iot.org/all-solutions/zigbee/

USB

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 329 阅读时长 ≈ 1 分钟

USB（Universal Serial Bus）是主机–设备型串行总线：2.0 / 3.x / USB-C，供电与数据一体，广泛用于 PC 外设、调试下载、存储。下面从「拓扑与角色 → 描述符与类 → CDC 虚拟串口 → 与 UART 的关系 → 嵌入式 Device 开发」顺序写清楚。

主机–设备拓扑



flowchart LR
  Host[USB Host PC] --> Hub[Hub 可选]
  Hub --> Dev1[Device 键鼠]
  Hub --> Dev2[Device CDC 串口]

一、拓扑

  • Host 发起事务；Device 响应。
  • OTG 设备可切换 Host/Device（手机接 U 盘）。

二、速度等级

版本 速率（量级）
USB 2.0 HS 480 Mbps
USB 3.x 5 Gbps+
USB4 基于 Thunderbolt 生态

Full Speed 12 Mbps 仍常见于 MCU Device。

三、描述符与 Class

  • 设备描述符 → 配置 → 接口 → 端点。
  • Class：HID（键鼠）、MSC（U 盘）、CDC-ACM（虚拟 UART）、Audio、Video 等。
  • Vendor Specific：自定义 Bulk/Interrupt 端点 + 主机驱动/libusb。

四、CDC 虚拟串口

MCU 通过 USB CDC ACM 暴露 /dev/ttyACM0（Linux）或 COM 口（Windows），应用层与 UART 类似发字节，物理层是 USB 包。

与 RS232：USB 转串口 芯片（CH340、CP2102、FT232）内部即 UART ↔ USB 桥接。

五、嵌入式开发要点

  • STM32 USB Device Library、TinyUSB、ESP32-S2/S3 USB OTG。
  • 枚举失败：检查 D+/D-、1.5k 上拉（Full Speed Device）、供电与描述符。
  • USB 3 / Type-C：PD 协商、Alt Mode（DP/Thunderbolt）另论。

规范：https://www.usb.org/documents
