NFC

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 319 阅读时长 ≈ 1 分钟

NFC（Near Field Communication）是近场无线通信（约 < 10 cm）：13.56 MHz，基于 RFID 演进，支持读卡、点对点、支付与配网。下面从「工作模式 → Tag 类型 → NDEF → 与 Bluetooth/USB 配合 → 安全」顺序写清楚。

读卡模式



sequenceDiagram
  participant R as NFC Reader 手机
  participant T as NFC Tag 卡
  R->>T: 射频场供电 + 轮询
  T-->>R: NDEF URL / 文本

一、工作模式

模式 说明
Reader/Writer 读或写 passive Tag
Card Emulation 手机模拟门禁/交通卡
Peer-to-Peer 两设备交换小数据（较少用）

二、Tag 标准

  • Type 1~4 Tag：不同容量与协议（NFC Forum）。
  • MIFARE Classic/Ultralight：交通、门禁（Classic 安全性已弱，新项目慎用）。
  • ISO 14443 A/B、ISO 15693（稍远，仍近场）。

三、NDEF（NFC Data Exchange Format）

常用 payload 格式，可封装：

  • URI（打开网页）
  • 文本
  • Wi-Fi 配置（WSC）
  • Bluetooth LE 配对 OOB 数据

手机贴近 Tag 即可触发系统动作（依 OS 策略）。

四、与其它接口

  • Bluetooth：NFC 传递配对密钥，BLE 传大数据。
  • USB：PC 用 USB NFC 读卡器 开发调试。
  • 支付：EMVCo、HCE（Host Card Emulation）在 SE/TEE 中存密钥。

五、开发

  • Android：NfcAdapter、enableReaderMode。
  • MCU：PN532、MFRC522（SPI/I2C）+ 天线设计。
  • 安全：Tag 可只读；支付与门禁依赖芯片级密钥，勿明文存敏感数据于可写 Tag。

Bluetooth

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 315 阅读时长 ≈ 1 分钟

蓝牙（Bluetooth） 是短距离无线标准：2.4 GHz ISM，经典分为 BR/EDR（经典蓝牙） 与 BLE（低功耗蓝牙，Bluetooth Low Energy）。下面从「BLE 架构 → GATT 服务 → 配对与安全 → 与 Zigbee/NFC 对照 → 开发」顺序写清楚。

BLE GATT 模型



flowchart TB
  Central[Central 手机] -->|连接| Peripheral[Peripheral 设备]
  Peripheral --> Svc[Service UUID]
  Svc --> Char[Characteristic 读写 Notify]

一、BLE 角色

角色 说明
Central 发起连接，如手机、网关
Peripheral 广播、被连接，如手环、温湿度计
Broadcaster / Observer 仅广播/扫描（Beacon）

连接后通过 ATT/GATT 读写特征值（Characteristic）。

二、GATT 模型

  • UUID：16 位标准 UUID 或 128 位自定义。
  • Notify/Indicate：外设主动推送数据，省 polling 功耗。

三、配对与安全

  • Just Works / Passkey / OOB 等配对模式。
  • LE Secure Connections（ECDH）防中间人。
  • 与 NFC tap-to-pair：NFC 交换临时信息辅助 BLE 配对。

四、经典蓝牙 vs BLE

经典 BLE
功耗 较高 极低
吞吐 音频、SPP 串口 小数据、传感器
协议 RFCOMM、A2DP 等 GATT

音频耳机等多用 经典 + BLE 双模芯片。

五、开发工具

  • nRF Connect（手机抓包 GATT）。
  • 芯片：Nordic nRF、ESP32（Bluedroid/NimBLE）、TI CC2340。
  • 与 USB：BLE dongle 常通过 USB 接 PC；逻辑仍是无线 GATT。

官方：https://www.bluetooth.com/specifications/

LoRaWAN

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 337 阅读时长 ≈ 1 分钟

LoRaWAN 是基于 LoRa 物理层的远距离广域网协议：星型拓扑，终端 ↔ 网关 ↔ 网络服务器，低功耗、公里级距离、kbps 级速率。下面从「频段与速率 → Class A/B/C → 入网与密钥 → 与 CoAP/MQTT → 应用场景」顺序写清楚。

星型拓扑



flowchart TB
  Dev1[终端节点] --> GW[LoRa 网关]
  Dev2[终端节点] --> GW
  GW --> NS[Network Server]
  NS --> App[应用服务器]

一、架构

  • Gateway：只做射频转发，不解密应用 payload（取决于模式）。
  • ADR（Adaptive Data Rate）：网络侧调节 SF/功率平衡距离与容量。

二、区域参数

区域 典型频段
EU868 863–870 MHz
US915 902–928 MHz
CN470 470–510 MHz

需遵守当地无线电法规；模块需合规认证。

三、设备 Class

Class 下行窗口 功耗
A 仅上行后两个短窗口 最低，传感器常用
B 附加信标窗口 中
C 几乎常开接收 高，供电设备

四、安全

  • Join：OTAA（Over-The-Air Activation，推荐）或 ABP（预置密钥）。
  • AES-128：NwkSKey、AppSKey 分层加密与完整性。
  • 应用层仍可封装 CoAP 或自定义二进制。

五、与其它物联网协议

  • 长距离、低带宽、电池 → LoRaWAN。
  • 有 Wi-Fi/以太网、高吞吐 → MQTT、HTTP。
  • 局域 mesh → Zigbee、Bluetooth Mesh。

开源栈：LoRaMac-node、Semtech LoRaWAN Stack；云平台：TTN、ChirpStack 等。

CoAP

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 358 阅读时长 ≈ 1 分钟

CoAP（Constrained Application Protocol，RFC 7252）是面向受限设备的应用层协议：二进制紧凑、基于 UDP（可 DTLS 加密），语义类似 REST（GET/PUT/POST/DELETE），与 HTTP 对照学习。下面从「报文结构 → 请求响应 → Observe 订阅 → 与 MQTT 对照 → 应用场景」顺序写清楚。

REST over UDP



sequenceDiagram
  participant C as CoAP Client
  participant S as CoAP Server
  C->>S: GET /temp
  S-->>C: 2.05 Content 25.3
  C->>S: Observe 订阅
  S-->>C: 推送变化

一、设计目标

  • 低开销：适合 MCU、6LoWPAN、低带宽链路。
  • 异步：支持 Separate 响应（ACK 先回，结果稍后 CON 通知）。
  • 发现：.well-known/core 资源目录。

默认端口 5683（CoAPS 5684）。

二、报文（简化）

Type 含义
CON 需确认
NON 不需确认
ACK 确认
RST 复位

Code：0.xx 请求（GET=0.01），2.xx 成功，4.xx/5.xx 错误（类比 HTTP）。

三、Observe（RFC 7641）

客户端带 Observe Option 订阅资源；服务器在资源变化时 NOTIFY，适合传感器推送，比轮询省流量。

四、与 MQTT

CoAP MQTT
模型 REST 资源 发布/订阅 Topic
传输 UDP 为主 TCP 常见
代理 CoAP-HTTP 代理 Broker 中心化

物联网选型：资源型设备、LwM2M（基于 CoAP）vs 海量消息经 Broker 的 MQTT。

五、应用

  • 智能抄表、楼宇传感器、Edge 网关 南向 CoAP、北向 HTTP/MQTT。
  • 安全：DTLS 预共享密钥或证书；与 LoRaWAN 可组合（应用 payload 再解析）。

库：libcoap、aiocoap（Python）、Californium（Java）。

LIN

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 339 阅读时长 ≈ 1 分钟

LIN（Local Interconnect Network）是低成本单主多从串行总线：基于 UART 异步字符，单线（+ GND），最高约 20 kbps，常见于汽车车身（门窗、座椅、传感器）。下面从「帧结构 → 调度表 → 与 CAN 的分工 → 硬件 → 开发注意」顺序写清楚。

单主多从



flowchart LR
  Master[LIN Master ECU] --- Bus[LIN 总线]
  S1[从节点 门窗] --- Bus
  S2[从节点 座椅] --- Bus

一、角色

  • Master：通常由 Body ECU 担任，发送 Header（含 PID）。
  • Slave：响应 Data 或发布自身数据；无仲裁，时隙由 Master 调度。

二、帧结构（简化）

  • Break：显性低电平较长，同步从机。
  • PID：含 6 位 ID + 2 位奇偶。
  • Checksum：Classic 或 Enhanced（LIN 2.x）。

三、调度表（Schedule Table）

Master 按固定周期发送各 Frame ID，保证确定性延迟；配置在 LDF（LIN Description File）中，工具链生成驱动代码。

四、与 CAN

LIN CAN
成本 低（常单线） 收发器稍贵
速率 ~20 kbps 最高 Mbps 级
拓扑 单主 多主
用途 非安全、低带宽 动力、底盘、网关

网关 ECU 常同时接 CAN 与多条 LIN 总线。

五、硬件与调试

  • 物理层：12V 系统常见，收发器如 TJA1021。
  • 调试：LIN 分析仪、USB-LIN 适配器；协议依 LIN 2.0/2.1/2.2 与 ISO 17987。

与 RS232 不同：LIN 有固定 Break/Sync 与 PID 语义，不是裸串口文本。

CAN

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 373 阅读时长 ≈ 1 分钟

CAN（Controller Area Network）是差分串行现场总线：多主、按 ID 仲裁、硬件 CRC 与 ACK，广泛用于汽车、工业控制。下面从「帧结构 → 仲裁与优先级 → 速率与拓扑 → CAN FD → 与 LIN/RS485 对照」顺序写清楚。

总线拓扑



flowchart LR
  ECU1[ECU 节点 1] --- BUS[CAN_H / CAN_L 总线]
  ECU2[ECU 节点 2] --- BUS
  ECU3[ECU 节点 3] --- BUS

一、经典 CAN 帧（概念）

字段 说明
仲裁 ID 11 位（标准）或 29 位（扩展），越小优先级越高
RTR 远程帧（较少用）
DLC 数据长度 0~8 字节
Data 载荷
CRC + ACK 硬件检错与确认

二、多主仲裁

总线空闲时多个节点可同时发送；ID 仲裁时逐 bit 比较，发显性 0 的胜出，失败者自动退为接收方，无中心主站。

三、速率与长度

速率 典型最大总线长度（粗估）
1 Mbps 数十米
500 kbps ~100m
125 kbps 更长

实际以收发器、电缆与拓扑仿真为准。

四、CAN FD

  • 数据段可 > 8 字节（最高 64），数据段波特率可高于仲裁段。
  • 新车载网络大量采用 CAN FD；旧 ECU 可能仅 Classic CAN。

MCU 侧：bxCAN、FDCAN 外设 + 收发器（TJA1050 等）。

五、与其它总线

总线 场景
LIN 车身低成本传感器，单主
RS485 + Modbus RTU 工业 PLC
CAN 汽车、机器人关节、安全相关

上层协议：CANopen、J1939、UDS（诊断）等建立在 CAN 帧之上。

SPI

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 338 阅读时长 ≈ 1 分钟

SPI（Serial Peripheral Interface）是四线同步全双工总线：SCLK、MOSI、MISO、CS（片选），主设备提供时钟，从设备在 CS 有效期间交换数据。下面从「模式 0~3 → 多从机拓扑 → 速率与布线 → 典型外设 → 与 I2C 对照」顺序写清楚。

一主多从



flowchart LR
  M[Master] -->|SCLK MOSI MISO| Flash[Flash CS0]
  M -->|独立 CS| SD[SD 卡 CS1]

一、信号

线 方向（相对 Master） 说明
SCLK 输出 时钟
MOSI 输出 Master Out Slave In
MISO 输入 Master In Slave Out
CS/SS 输出 低有效选中从机

二、CPOL / CPHA（模式 0~3）

  • CPOL：空闲时 SCLK 电平（0=低，1=高）。
  • CPHA：第几个边沿采样（0=第一边沿，1=第二边沿）。

主从 模式必须一致（数据手册会写 Mode 0 等）。

三、多从机

  • 独立 CS：每个从机一根 CS，MOSI/MISO/SCLK 共享（MISO 需三态，未选中不高驱）。
  • Daisy Chain：如部分 Shift Register、LED 驱动，数据串行穿过多芯片。

四、典型应用

  • Flash（W25Q）、SD 卡（SPI 模式）、ADC/DAC、TFT 屏、RF 模块（NRF24L01）。
  • 速率常 MHz~ tens of MHz，短 PCB 走线；长距离不如 RS485。

五、与 I2C

SPI I2C
线数 4+（每从机 +CS） 2
速度 通常更快 400k/1M 常见
寻址 硬件 CS 7 位地址
双工 全双工 半双工

异步调试打印仍用 UART。

I2C

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 396 阅读时长 ≈ 1 分钟

I²C（Inter-Integrated Circuit）是两线同步串行总线：SDA（数据）、SCL（时钟），多主多从，用 7 位/10 位地址寻址。下面从「时序 → 寻址与读写 → 上拉与速率 → 典型外设 → 与 SPI/UART 对照」顺序写清楚。

总线拓扑



flowchart TB
  Master[主设备 MCU] --- SCL[SCL 时钟]
  Master --- SDA[SDA 数据]
  SDA --> S1[从设备 地址 0x48]
  SDA --> S2[从设备 地址 0x50]
  SCL --> S1
  SCL --> S2

一、信号与起始/停止

  • 空闲：SDA、SCL 均为高（靠上拉电阻）。
  • START：SCL 高时 SDA 下降沿。
  • STOP：SCL 高时 SDA 上升沿。
  • 数据位：SCL 低时 SDA 变化，SCL 高时采样。

二、7 位地址帧（写）

读操作：写寄存器指针 → 重复 START → 读地址 + 读数据 + NACK + STOP。

三、速率模式

模式 速率
Standard 100 kHz
Fast 400 kHz
Fast Mode Plus 1 MHz
High Speed 3.4 MHz（较少用）

上拉电阻：常见 2.2k~10k（3.3V、总线电容与速率相关）；长电缆或多设备需降低电容、可能用 I2C 缓冲器/扩展器。

四、典型设备

  • EEPROM（24Cxx）、RTC（DS3231）、IMU、OLED 小屏、PMIC、GPIO 扩展（PCF8574）。
  • 同一地址冲突：部分芯片有 ADDR 引脚改地址；否则需不同总线（I2C mux）。

五、与 SPI、UART

总线 线数 速度 特点
I2C 2 + GND 中 多从、地址、开漏
SPI 4+ 高 全双工、无标准地址
UART 2 + GND 中 点对点、异步

CAN 用于车载/工业现场总线，抗干扰与仲裁不同于 I2C。

RS485

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 410 阅读时长 ≈ 1 分钟

RS-485（TIA-485）是差分半双工串行标准： A/B 两根线传输，抗共模干扰强，支持总线型多机（一主多从或令牌），波特率可达 Mbps 级、距离 千米 级（降速）。下面从「拓扑与终端电阻 → 半双工收发 → 与 Modbus RTU → 与 RS232/UART 的关系 → 布线注意」顺序写清楚。

总线型拓扑



flowchart LR
  M[主站] --- BUS[A/B 差分总线]
  S1[从站 1] --- BUS
  S2[从站 2] --- BUS
  T[120Ω 终端电阻] --- BUS

一、拓扑

  • 半双工：同一时刻只能一个方向发送；需 DE/RE 引脚控制收发器方向。
  • 共模范围：约 -7V ~ +12V，适合工业现场。

二、UART + RS485 收发器

MCU UART 接 MAX485/SN65HVD 等：

发送前切换 DE；切换后需等待收发器稳定再发首字节，避免毛刺。

三、与 Modbus RTU

Modbus RTU 在 RS485 上最常见：主站轮询、从站地址 1~247、CRC16 帧尾。
与 Modbus ASCII 比，RTU 更紧凑、工业现场更常用。

四、对比 RS232

项目 RS232 RS485
信号 单端 差分
距离 短 长
节点数 点对点为主 多机总线
双工 全双工常见 半双工为主

五、布线注意

  • 双绞线、屏蔽层单端接地（现场依规范）。
  • 终端电阻 120Ω 仅在总线两端；中间节点不加。
  • GND 参考：虽为差分，仍建议可靠参考地，避免共模超范围。
  • ESD 与浪涌：户外/电机旁加保护器件。

RS232

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 332 阅读时长 ≈ 1 分钟

RS-232 是经典的串行物理层标准：单端信号、±3~15V 电平（相对信号地），定义 DTE/DCE 引脚（TXD/RXD/RTS/CTS 等）。下面从「电平与距离 → 与 TTL UART 转换 → 三线制通信 → 流控 → 与现代接口的关系」顺序写清楚。

DTE-DCE 连接



flowchart LR
  PC[DTE PC] -->|TXD RXD GND| Conv[USB-RS232 转换]
  Conv --> Dev[DCE 设备]

一、电平与特点

  • 逻辑 1：负电压（如 -5V ~ -15V）
  • 逻辑 0：正电压（如 +5V ~ +15V）
  • 单端：抗干扰弱于 RS485 差分；距离通常 < 15m（与波特率反相关）。
  • 点对点：多机需额外切换，不像 RS485 总线型。

MCU 侧为 TTL UART（0/3.3V），需 MAX232、SP3232 等芯片做电平转换。

二、最小三线连接

交叉连接 TX/RX；不要把 RS232 口直接接 MCU UART 引脚。

三、流控（可选）

信号 作用
RTS/CTS 硬件流控，防缓冲区溢出
DTR/DSR 设备就绪（Modem 时代遗留）
软件流控 XON/XOFF 字符

嵌入式调试常 115200 8N1 无流控。

四、应用场景

  • 工业仪器、老式 PLC、条码枪 DB9 口。
  • USB 转 RS232 dongle 在 PC 上模拟 COM 口。
  • 长距离、多机、抗干扰场景优先 RS485 或 以太网（Modbus TCP）。

协议层仍可能是 Modbus RTU 或自定义 ASCII 帧。
