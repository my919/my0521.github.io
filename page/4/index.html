一、前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

二、MySQL 镜像选择

1. 官方镜像（推荐）

  • 仓库：mysql（Docker Hub 官方库，由 Oracle / MySQL 团队维护）。
  • 常用标签：
    • mysql:8.0：8.0 长期维护线，生态兼容面广（WordPress、旧驱动等多以 8.0 为基准）。
    • mysql:8.4 或 mysql:lts：较新的 LTS 线（以 Docker Hub mysql tags 为准）。
  • 生产建议：固定小版本标签（如 mysql:8.0.40）或记录 digest，避免 latest 漂移导致行为变化。

2. 变体说明

需求 说明
默认认证插件 8.0 起默认 caching_sha2_password；老客户端不支持时需调整 --default-authentication-plugin 或升级客户端（MySQL 8.4 已移除 mysql_native_password，迁移前查发行说明）。
ARM64（Apple Silicon 等） 官方 mysql 多架构镜像一般可直接拉取；若某标签缺架构，换标签或查 Hub OS/ARCH。
极简/定制 社区有 bitnami/mysql 等，参数与路径与官方不同，切换镜像时需对照该镜像文档。

3. 字符集与排序规则

容器内建议在 command 或 my.cnf 中显式指定 utf8mb4，与业务库一致，避免默认与连接串不一致。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式运行 MySQL，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 MySQL 一键部署：由面板负责镜像版本、数据持久化、端口映射与（可选）计划备份，启停与日志可在界面查看。与下文 docker run / Compose / K8s 中的环境变量、卷与字符集语义对齐或排障时，自 # 三 起各节仍可作对照。适合单台 VPS、家庭服务器等「一台机子上稳态跑库」的场景。

使用 Nacos 托管 Seata 规则时，常见做法是在 Nacos 创建 seata.properties（或按 Server 2.5 文档拆分多 dataId），并包含 service.vgroupMapping.<应用tx-group>=default 等项；Server 与业务应用均指向同一 Nacos 地址与命名空间。具体 Key 列表可参考 Seata 仓库 script/config-center/config.txt 并结合当前 Server 版本说明裁剪。

联调检查

  1. 日志：发起全局事务时，各参与服务日志中 XID 应一致且随请求变化。

  3. 控制台：Server 2.x 控制台可观察全局事务与锁（端口以实际镜像/启动参数为准）。

Sentinel 提供流量控制、熔断降级、系统自适应保护等能力；在 Spring Cloud Alibaba 中通过 spring-cloud-starter-alibaba-sentinel 开箱接入 Web 与常见远程调用场景。SCA 2025.1.0.0 将 Sentinel 核心库对齐到 1.8.9，并与 Spring Boot 4.x / Jackson 3.x 兼容（见 Release 说明）。BOM 与 Gradle 工程见 Spring Cloud Alibaba 与 Gradle 从零搭建。

SCA BOM 2025.1.0.0 以 GitHub Releases 为准
Sentinel Core（BOM） 1.8.9 spring-cloud-alibaba-dependencies 中 sentinel.version
Sentinel Dashboard 与 1.8.x 控制台匹配 建议从 Sentinel Releases 下载 sentinel-dashboard-1.8.9.jar（或与 1.8.9 同线的控制台包）

规则持久化（简述）

默认规则存内存；生产可将流控、降级等规则放到 Nacos、Redis 等数据源，使用 sentinel-datasource-* 与 SCA 文档中的 spring.cloud.sentinel.datasource 配置。与 Nacos 同栈时，可统一由 Nacos 推送规则。

Nacos 作注册中心与配置中心时，Server 大版本应与客户端同世代，并与 Spring Cloud Alibaba（SCA） BOM 里管理的 nacos-client 一致。站内 Gradle 搭建与 SCA BOM 选型见 Spring Cloud Alibaba 与 Gradle 从零搭建。

与 Spring Cloud Alibaba 的版本关系

SCA 2025.1.x 主线

组件 建议版本 说明
Spring Cloud Alibaba BOM 2025.1.0.0（及后续 2025.1.0.x 补丁） 以 GitHub Releases 为准
nacos-client（由 BOM 管理） 3.1.1 2025.1.0.0 发行说明明确从 3.0.3 升级至 3.1.1
Nacos Server 3.1.x，本文镜像钉 v3.1.1 与 nacos-client 3.1.x 同世代；镜像见 Docker Hub nacos/nacos-server

应用侧 spring.cloud.nacos.discovery.server-addr 仍指向 8848 所在地址即可；客户端由 SCA 与 Nacos 协议栈处理 gRPC 等端口，一般无需在业务配置里手写 9848/9849。

Nacos 3.x 端口与控制台

Nacos 3.x 默认将控制台与核心进程分离：控制台常见为 8080（路径 /index.html），8848 仍为服务端主端口；容器示例还会映射 9848（及集群场景下相关端口）。与 Nacos 2.x 单端口习惯不同，部署防火墙与 Service 端口时要同时放行控制台与客户端所需端口。官方说明见 nacos-group/nacos-docker README。

自 Nacos 2.2.1 起镜像不再内置默认 NACOS_AUTH_*，必须自行传入，否则启动报错；Nacos 3.x 快速启动示例同样要求 NACOS_AUTH_TOKEN、NACOS_AUTH_IDENTITY_KEY、NACOS_AUTH_IDENTITY_VALUE。以下为占位符，生产环境请换成高强度随机值并纳入密钥管理。

外置 MySQL（容器连接库表）

Nacos 官方镜像通过环境变量切换存储：不设置 SPRING_DATASOURCE_PLATFORM（或为空）时使用内嵌 Derby；设为 mysql 时使用外置 MySQL。变量名与 nacos-docker 中 env/nacos-standalone-mysql.env 一致。

1. 前置：建库与表结构

  1. 在 MySQL 8.x 中创建库（示例库名 nacos_devtest），字符集 utf8mb4 / 排序规则 utf8mb4_unicode_ci（与官方 Compose 一致即可）。
  2. 为 Nacos 单独业务账号并授权该库（最小权限）。
  3. 首次部署前在目标库执行与 Server 版本匹配 的 mysql-schema.sql（官方仓库路径随版本调整，当前可在 Nacos 仓库中查找 mysql-schema.sql，例如 nacos 仓库内 mysql 插件资源目录 下的脚本；升级 Server 大版本时务必对照发行说明是否需迁移脚本）。
  4. 容器网络： MYSQL_SERVICE_HOST 必须填 Nacos 容器能解析到的地址——同 Compose 栈内用服务名（如 mysql）；宿主机上的库在 Linux 上常用宿主机网关 IP 或 host.docker.internal（视 Docker 版本而定），不要用 127.0.0.1 指宿主机上的 MySQL。

2. 常用环境变量（官方镜像）

变量 含义 示例
SPRING_DATASOURCE_PLATFORM 固定为 mysql 启用外置库 mysql
MYSQL_SERVICE_HOST MySQL 主机名或 IP mysql（同网络服务名）
MYSQL_SERVICE_PORT 端口 3306
MYSQL_SERVICE_DB_NAME 库名 nacos_devtest
MYSQL_SERVICE_USER / MYSQL_SERVICE_PASSWORD 账号密码 由你方创建
MYSQL_SERVICE_DB_PARAM JDBC 查询串（时区、SSL 等） 见下方示例
MYSQL_DATABASE_NUM 多数据源数量 一般为 1，默认可不写

OpenSSL 证书与密钥 完整指南

OpenSSL 是生成、管理非对称密钥和数字证书的标准工具，广泛用于 HTTPS、SSL/TLS、身份认证、加密通信等场景。

一、核心概念（快速看懂）

  1. 私钥（private key）：.key / .pem，必须保密，用于解密、签名
  2. 公钥（public key）：从私钥导出，公开分发，用于加密、验签
  3. 证书（certificate）：.crt / .pem，包含公钥 + 身份信息 + 签名，证明公钥合法
  4. CSR（证书签名请求）：.csr，向 CA 机构申请正式证书的文件

二、最常用命令（直接用）

1. 生成 RSA 私钥（无密码）

  • 2048 是密钥长度（安全推荐）
  • 生成后千万不要泄露

2. 生成带密码保护的私钥（更安全）

每次使用会要求输入密码。

3. 从私钥导出公钥

三、生成自签名证书（开发/测试必备）

自签名证书 = 私钥 + 自己签发的证书
适合本地开发、内网测试，不能用于公网生产环境。

一步生成 私钥 + 证书（有效期 10 年）

最终得到两个文件：

  • private.key：私钥
  • cert.crt：自签名证书

四、生成 CSR（向 CA 申请正式证书）

如果你要申请阿里云/腾讯云/Let’s Encrypt 正规证书，必须先生成 CSR。

六、格式转换（最常见需求）

1. PEM 转 PKCS#12（.pfx / .p12，Windows/IIS 用）

2. 从 PFX 提取 私钥 + 证书

七、生产环境标准流程

  1. 生成安全私钥（4096 位，带密码）
  2. 生成 CSR
  3. 提交 CSR 给 CA → 获取正式证书
  4. 部署证书（Nginx/Apache/IIS）

总结

  1. 开发用：自签名证书（私钥 + crt）
  2. 生产用：CSR 申请正规证书
  3. 必备命令：生成密钥、查看证书、格式转换、验证匹配
  4. 私钥绝对不能泄露，泄露等于证书失效
