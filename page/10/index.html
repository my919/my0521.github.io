LIN

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 348 阅读时长 ≈ 1 分钟

LIN（Local Interconnect Network）是低成本单主多从串行总线：基于 UART 异步字符，单线（+ GND），最高约 20 kbps，常见于汽车车身（门窗、座椅、传感器）。下面从「帧结构 → 调度表 → 与 CAN 的分工 → 硬件 → 开发注意」顺序写清楚。

单主多从



flowchart LR
  Master[LIN Master ECU] --- Bus[LIN 总线]
  S1[从节点 门窗] --- Bus
  S2[从节点 座椅] --- Bus

一、角色

  • Master：通常由 Body ECU 担任，发送 Header（含 PID）。
  • Slave：响应 Data 或发布自身数据；无仲裁，时隙由 Master 调度。

二、帧结构（简化）

  • Break：显性低电平较长，同步从机。
  • PID：含 6 位 ID + 2 位奇偶。
  • Checksum：Classic 或 Enhanced（LIN 2.x）。

三、调度表（Schedule Table）

Master 按固定周期发送各 Frame ID，保证确定性延迟；配置在 LDF（LIN Description File）中，工具链生成驱动代码。

四、与 CAN

LIN CAN
成本 低（常单线） 收发器稍贵
速率 ~20 kbps 最高 Mbps 级
拓扑 单主 多主
用途 非安全、低带宽 动力、底盘、网关

网关 ECU 常同时接 CAN 与多条 LIN 总线。

五、硬件与调试

  • 物理层：12V 系统常见，收发器如 TJA1021。
  • 调试：LIN 分析仪、USB-LIN 适配器；协议依 LIN 2.0/2.1/2.2 与 ISO 17987。

与 RS232 不同：LIN 有固定 Break/Sync 与 PID 语义，不是裸串口文本。

CAN

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 382 阅读时长 ≈ 1 分钟

CAN（Controller Area Network）是差分串行现场总线：多主、按 ID 仲裁、硬件 CRC 与 ACK，广泛用于汽车、工业控制。下面从「帧结构 → 仲裁与优先级 → 速率与拓扑 → CAN FD → 与 LIN/RS485 对照」顺序写清楚。

总线拓扑



flowchart LR
  ECU1[ECU 节点 1] --- BUS[CAN_H / CAN_L 总线]
  ECU2[ECU 节点 2] --- BUS
  ECU3[ECU 节点 3] --- BUS

一、经典 CAN 帧（概念）

字段 说明
仲裁 ID 11 位（标准）或 29 位（扩展），越小优先级越高
RTR 远程帧（较少用）
DLC 数据长度 0~8 字节
Data 载荷
CRC + ACK 硬件检错与确认

二、多主仲裁

总线空闲时多个节点可同时发送；ID 仲裁时逐 bit 比较，发显性 0 的胜出，失败者自动退为接收方，无中心主站。

三、速率与长度

速率 典型最大总线长度（粗估）
1 Mbps 数十米
500 kbps ~100m
125 kbps 更长

实际以收发器、电缆与拓扑仿真为准。

四、CAN FD

  • 数据段可 > 8 字节（最高 64），数据段波特率可高于仲裁段。
  • 新车载网络大量采用 CAN FD；旧 ECU 可能仅 Classic CAN。

MCU 侧：bxCAN、FDCAN 外设 + 收发器（TJA1050 等）。

五、与其它总线

总线 场景
LIN 车身低成本传感器，单主
RS485 + Modbus RTU 工业 PLC
CAN 汽车、机器人关节、安全相关

上层协议：CANopen、J1939、UDS（诊断）等建立在 CAN 帧之上。

SPI

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 347 阅读时长 ≈ 1 分钟

SPI（Serial Peripheral Interface）是四线同步全双工总线：SCLK、MOSI、MISO、CS（片选），主设备提供时钟，从设备在 CS 有效期间交换数据。下面从「模式 0~3 → 多从机拓扑 → 速率与布线 → 典型外设 → 与 I2C 对照」顺序写清楚。

一主多从



flowchart LR
  M[Master] -->|SCLK MOSI MISO| Flash[Flash CS0]
  M -->|独立 CS| SD[SD 卡 CS1]

一、信号

线 方向（相对 Master） 说明
SCLK 输出 时钟
MOSI 输出 Master Out Slave In
MISO 输入 Master In Slave Out
CS/SS 输出 低有效选中从机

二、CPOL / CPHA（模式 0~3）

  • CPOL：空闲时 SCLK 电平（0=低，1=高）。
  • CPHA：第几个边沿采样（0=第一边沿，1=第二边沿）。

主从 模式必须一致（数据手册会写 Mode 0 等）。

三、多从机

  • 独立 CS：每个从机一根 CS，MOSI/MISO/SCLK 共享（MISO 需三态，未选中不高驱）。
  • Daisy Chain：如部分 Shift Register、LED 驱动，数据串行穿过多芯片。

四、典型应用

  • Flash（W25Q）、SD 卡（SPI 模式）、ADC/DAC、TFT 屏、RF 模块（NRF24L01）。
  • 速率常 MHz~ tens of MHz，短 PCB 走线；长距离不如 RS485。

五、与 I2C

SPI I2C
线数 4+（每从机 +CS） 2
速度 通常更快 400k/1M 常见
寻址 硬件 CS 7 位地址
双工 全双工 半双工

异步调试打印仍用 UART。

I2C

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 405 阅读时长 ≈ 1 分钟

I²C（Inter-Integrated Circuit）是两线同步串行总线：SDA（数据）、SCL（时钟），多主多从，用 7 位/10 位地址寻址。下面从「时序 → 寻址与读写 → 上拉与速率 → 典型外设 → 与 SPI/UART 对照」顺序写清楚。

总线拓扑



flowchart TB
  Master[主设备 MCU] --- SCL[SCL 时钟]
  Master --- SDA[SDA 数据]
  SDA --> S1[从设备 地址 0x48]
  SDA --> S2[从设备 地址 0x50]
  SCL --> S1
  SCL --> S2

一、信号与起始/停止

  • 空闲：SDA、SCL 均为高（靠上拉电阻）。
  • START：SCL 高时 SDA 下降沿。
  • STOP：SCL 高时 SDA 上升沿。
  • 数据位：SCL 低时 SDA 变化，SCL 高时采样。

二、7 位地址帧（写）

读操作：写寄存器指针 → 重复 START → 读地址 + 读数据 + NACK + STOP。

三、速率模式

模式 速率
Standard 100 kHz
Fast 400 kHz
Fast Mode Plus 1 MHz
High Speed 3.4 MHz（较少用）

上拉电阻：常见 2.2k~10k（3.3V、总线电容与速率相关）；长电缆或多设备需降低电容、可能用 I2C 缓冲器/扩展器。

四、典型设备

  • EEPROM（24Cxx）、RTC（DS3231）、IMU、OLED 小屏、PMIC、GPIO 扩展（PCF8574）。
  • 同一地址冲突：部分芯片有 ADDR 引脚改地址；否则需不同总线（I2C mux）。

五、与 SPI、UART

总线 线数 速度 特点
I2C 2 + GND 中 多从、地址、开漏
SPI 4+ 高 全双工、无标准地址
UART 2 + GND 中 点对点、异步

CAN 用于车载/工业现场总线，抗干扰与仲裁不同于 I2C。

RS485

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 419 阅读时长 ≈ 1 分钟

RS-485（TIA-485）是差分半双工串行标准： A/B 两根线传输，抗共模干扰强，支持总线型多机（一主多从或令牌），波特率可达 Mbps 级、距离 千米 级（降速）。下面从「拓扑与终端电阻 → 半双工收发 → 与 Modbus RTU → 与 RS232/UART 的关系 → 布线注意」顺序写清楚。

总线型拓扑



flowchart LR
  M[主站] --- BUS[A/B 差分总线]
  S1[从站 1] --- BUS
  S2[从站 2] --- BUS
  T[120Ω 终端电阻] --- BUS

一、拓扑

  • 半双工：同一时刻只能一个方向发送；需 DE/RE 引脚控制收发器方向。
  • 共模范围：约 -7V ~ +12V，适合工业现场。

二、UART + RS485 收发器

MCU UART 接 MAX485/SN65HVD 等：

发送前切换 DE；切换后需等待收发器稳定再发首字节，避免毛刺。

三、与 Modbus RTU

Modbus RTU 在 **RS485** 上最常见：**主站轮询**、**从站地址 1~247**、**CRC16** 帧尾。

与 Modbus ASCII 比，RTU 更紧凑、工业现场更常用。

四、对比 RS232

项目 RS232 RS485
信号 单端 差分
距离 短 长
节点数 点对点为主 多机总线
双工 全双工常见 半双工为主

五、布线注意

  • 双绞线、屏蔽层单端接地（现场依规范）。
  • 终端电阻 120Ω 仅在总线两端；中间节点不加。
  • GND 参考：虽为差分，仍建议可靠参考地，避免共模超范围。
  • ESD 与浪涌：户外/电机旁加保护器件。

RS232

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 344 阅读时长 ≈ 1 分钟

RS-232 是经典的串行物理层标准：单端信号、±3~15V 电平（相对信号地），定义 DTE/DCE 引脚（TXD/RXD/RTS/CTS 等）。下面从「电平与距离 → 与 TTL UART 转换 → 三线制通信 → 流控 → 与现代接口的关系」顺序写清楚。

DTE-DCE 连接



flowchart LR
  PC[DTE PC] -->|TXD RXD GND| Conv[USB-RS232 转换]
  Conv --> Dev[DCE 设备]

一、电平与特点

  • 逻辑 1：负电压（如 -5V ~ -15V）
  • 逻辑 0：正电压（如 +5V ~ +15V）
  • 单端：抗干扰弱于 RS485 差分；距离通常 < 15m（与波特率反相关）。
  • 点对点：多机需额外切换，不像 RS485 总线型。

MCU 侧为 TTL UART（0/3.3V），需 MAX232、SP3232 等芯片做电平转换。

二、最小三线连接

交叉连接 TX/RX；不要把 RS232 口直接接 MCU UART 引脚。

三、流控（可选）

信号 作用
RTS/CTS 硬件流控，防缓冲区溢出
DTR/DSR 设备就绪（Modem 时代遗留）
软件流控 XON/XOFF 字符

嵌入式调试常 115200 8N1 无流控。

四、应用场景

  • 工业仪器、老式 PLC、条码枪 DB9 口。
  • USB 转 RS232 dongle 在 PC 上模拟 COM 口。
  • 长距离、多机、抗干扰场景优先 RS485 或 以太网（Modbus TCP）。

协议层仍可能是 Modbus RTU 或自定义 ASCII 帧。

UART

发表于 2026-05-01 更新于 2026-05-31 分类于 Embedded 本文字数： 377 阅读时长 ≈ 1 分钟

UART（Universal Asynchronous Receiver/Transmitter，通用异步收发器）是最常见的串行异步通信硬件：两根线（TX/RX）逐 bit 传输，无同步时钟线。下面从「帧格式 → 波特率 → 与 RS232/RS485 的关系 → MCU 配置要点 → 调试」顺序写清楚。

点对点连接



flowchart LR
  MCU1[MCU A TX] -->|RX| MCU2[MCU B RX]
  MCU2 -->|TX| MCU1

一、异步帧结构

  • 空闲：线路高电平。
  • 起始位：拉低，通知接收方开始采样。
  • LSB 先发：数据位从低位到高位。
  • 校验：None / Odd / Even（可选）。
  • 停止位：1 或 2 位高电平，恢复空闲。

二、波特率

常见：9600、115200、921600。收发双方波特率必须一致（误差通常 < 2%）。

三、电平与接口层

层次 说明
TTL UART MCU 引脚 3.3V/5V，直连 USB-TTL 模块
RS232 ± 电平，PC 老式串口、部分工业设备
RS485 差分、半双工、多机总线，常经 UART+收发器

UART 指控制器逻辑；对外物理层常加 MAX232、MAX485 等芯片。

四、应用与调试

  • 日志打印、AT 指令（4G/Wi-Fi 模块）、GPS NMEA、Bootloader。
  • Linux：/dev/ttyUSB0，minicom / picocom / screen。
  • 注意：TX 接 RX 交叉；共地 GND 必须连接。

与 SPI、I2C 对照：UART 线少、距离短（TTL）、协议简单，无硬件从机地址。

Modbus ASCII

发表于 2026-05-01 更新于 2026-05-31 分类于 Modbus 本文字数： 360 阅读时长 ≈ 1 分钟

Modbus ASCII 用 ASCII 十六进制字符 传输 Modbus PDU，帧以 : 开始、CR LF 结束，校验为 LRC（纵向冗余）。适合人工调试与部分老式设备；工业现场吞吐量通常不如 Modbus RTU。下面从「帧格式 → LRC 计算 → 与 RTU 选型 → 示例」顺序写清楚。

与 RTU 对比



flowchart LR
  subgraph ascii [Modbus ASCII]
    A1[可读 HEX 字符] --> A2[LRC 校验]
  end
  subgraph rtu [Modbus RTU]
    R1[二进制 ADU] --> R2[CRC16]
  end
  M[主站] --> ascii
  M --> rtu

一、帧格式

示例（读保持寄存器，概念）：

  • : 起始。
  • 每字节用 两个 ASCII 十六进制字符（0-9 A-F）。
  • CR LF 结束（0x0D 0x0A）。

二、LRC

对 地址到数据末字节 求和（8 位），取二进制补码（256 - sum），再转两个 ASCII 十六进制字符。

RTU 使用 CRC16；ASCII 用 LRC，检错能力较弱但实现简单。

三、与 RTU / TCP

变体 编码 效率 场景
RTU 二进制 高 RS485 主流
ASCII 文本 HEX 低（约 2× 字节） 调试、老设备
TCP 二进制 + MBAP 高 以太网

同一 PDU 功能码 语义一致；切换链路层时注意地址与寄存器映射相同。

四、调试

  • 串口终端可直接粘贴 : 帧（若设备支持 ASCII 模式）。
  • 物理层常为 RS232 或 RS485 + UART。
  • 生产系统优先 RTU 或 TCP，ASCII 多用于维护口。

Modbus TCP

发表于 2026-05-01 更新于 2026-05-31 分类于 Modbus 本文字数： 352 阅读时长 ≈ 1 分钟

Modbus TCP 将 Modbus PDU 封装在 TCP/IP 上：默认端口 502，增加 MBAP（Modbus Application Protocol Header），无 CRC（由 TCP 保证）。下面从「MBAP 头 → 与 RTU 的 PDU 关系 → 连接模型 → 与网关 → 安全」顺序写清楚。

TCP 连接模型



flowchart LR
  SCADA[SCADA 主站] -->|TCP :502| PLC[PLC / 网关]
  PLC --> RTU[Modbus RTU 从站 经串口]

一、MBAP 头（7 字节）

字段 长度 说明
Transaction ID 2 事务标识，请求/响应配对
Protocol ID 2 固定 0
Length 2 后续字节数（Unit ID + PDU）
Unit ID 1 设备地址（经网关映射 RTU 从站）

其后为与 Modbus RTU 相同的 功能码 + 数据（无 CRC）。

二、示例（读保持寄存器）

响应 MBAP 中 Length 与 Transaction ID 与请求对应。

三、连接模型

  • 单连接多事务：常见一客户端对一 PLC 长连接 502。
  • 并发：多客户端连同一设备需注意 PLC 连接数限制。
  • 与 HTTP：不同协议；工业网关可能同时提供 Modbus TCP 与 OPC UA。

四、串口网关

Modbus TCP ↔ RTU 网关：
Unit ID 映射 RS485 从站地址；网关内维护 RS485 轮询时序。

五、安全

  • 502 明文、无认证 → 仅放工控内网或 VPN；勿暴露公网。
  • 现代方案：TLS 隧道、VPN、专用安全网关。
  • 与 Modbus ASCII 比：TCP 适合跨交换机、远程 SCADA。

Modbus RTU

发表于 2026-05-01 更新于 2026-05-31 分类于 Modbus 本文字数： 453 阅读时长 ≈ 2 分钟

Modbus RTU 是 Modbus 协议在二进制串行链路上的实现，最常见物理层为 RS485：主站轮询、从站地址、功能码、CRC16 结尾。下面从「ADU 帧 → 常用功能码 → 时序与 3.5 字符 → 与 ASCII/TCP 对照 → 调试工具」顺序写清楚。

主从轮询



sequenceDiagram
  participant M as 主站 PLC
  participant S as 从站 地址 1
  M->>S: 读保持寄存器 FC03
  S-->>M: 数据 + CRC
  M->>S: 写单个寄存器 FC06
  S-->>M: ACK

一、RTU 帧结构

  • 地址 0：广播（从站不应应答）。
  • CRC：对地址到数据末字节计算 Modbus CRC16。

示例（读保持寄存器 0x03）：主站发 01 03 00 00 00 0A C5 CD（含义依上下文解析）。

二、常用功能码

码 名称 说明
0x01 Read Coils 读线圈（位）
0x03 Read Holding Registers 读保持寄存器（16 位）
0x04 Read Input Registers 读输入寄存器
0x06 Write Single Register 写单寄存器
0x10 Write Multiple Registers 写多寄存器

异常应答：功能码 + 0x80，后跟异常码。

三、时序（RTU 特有）

帧间静默 ≥ 3.5 字符时间（与波特率相关），用于帧界定；波特率高时该间隔很短，实现需精确。

  • 115200 下对 MCU 中断延迟更敏感。
  • 半双工 RS485 需在发送前使能 DE。

四、与其它 Modbus

变体 链路 帧界定
RTU RS485/RS232 静默 + CRC
ASCII 串口 : 起 CRLF 止，LRC
TCP 以太网 MBAP 头 + 无 CRC

寄存器地址映射（40001 等）在文档与 PDU 偏移间需 减 1 转换，避免 off-by-one。

五、调试

  • Modbus Poll / Slave（Windows）、pymodbus、QModMaster（Linux）。
  • 抓包：串口监听或 RS485 分析仪。
  • 与 UART 关系：RTU 是应用层协议，底下是异步串口 + 485 收发器。

Modbus 组织：https://modbus.org/
