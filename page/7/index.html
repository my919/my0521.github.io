从弱熵源（用户口令）安全得到加密密钥，或生成不可预测随机数，是对称加密与 TLS 的基础。OpenSSL 提供 openssl rand、enc -pbkdf2、kdf 等。对称加密见 对称加密。

推荐实践

OpenSSL 数字签名与 HMAC：完整性、身份与推荐用法

数字签名证明「谁签署 + 内容未被改」；HMAC 在共享密钥下提供消息认证码（完整性 + 双方互信）。OpenSSL 分别通过 dgst -sign 与 dgst -hmac 实现。哈希选型见 哈希算法，密钥对见 非对称加密。

场景选型

场景 推荐 说明
软件发布、固件、JWT（RS256/ES256） RSA-PSS / ECDSA / Ed25519 + SHA-256 公钥可公开分发
TLS 证书链 CA 私钥签名 + SHA-256 见 OpenSSL 常用操作
API 请求鉴权（双方已有密钥） HMAC-SHA256 Webhook、AWS Signature V4 同类思路
口令验证存储 不适用裸 HMAC 用 PBKDF2 / Argon2 见 密钥派生

  participant A as 发布方
  participant B as 验证方
  A->>A: hash = SHA256(file)
  A->>A: sig = Sign_private(hash)
  A->>B: file + sig + cert
  B->>B: Verify_public(hash, sig)

一、数字签名（非对称）

1. 推荐算法

签名算法 摘要 推荐度
