QUIC 详解：基于 UDP 的可靠传输、TLS 集成与 HTTP/3

发表于 2026-05-01 更新于 2026-05-04 分类于 Protocol 本文字数： 550 阅读时长 ≈ 2 分钟

QUIC（IETF QUIC，RFC 9000）在 UDP 之上实现加密、多路复用、连接迁移与类 TCP 的可靠传输；HTTP/3（RFC 9114）将 HTTP 语义映射到 QUIC 流上。下面从「动机：TCP+TLS 的痛点 → 连接与流（原理） → TLS 1.3 集成 → 与 HTTP/2 对比 → curl 探测示例」顺序写清楚。

一、动机（原理）

问题 TCP 栈表现 QUIC 思路
队头阻塞 TCP 字节流级丢包阻塞后续所有应用数据 QUIC 在流级独立丢包恢复
握手 RTT 常需 TCP 三次握手 + TLS 往返 QUIC 常合并加密与传输握手（1-RTT）
NAT 重绑定 四元组变化即「新连接」 Connection ID 标识连接，支持连接迁移

二、连接、流与包（作用）

  • Connection：加密与拥塞控制的上下文。
  • Stream：单向或双向；HTTP/3 请求/响应映射在流上，互不影响（流级 HOL 缓解）。
  • Packet Number：单调递增，防 ACK 歧义（与 TCP 序号语义不同）。

三、TLS 1.3 与 QUIC（原理）

QUIC 的 TLS 1.3 用于密钥协商与握手认证；载荷使用 AEAD 加密。0-RTT 可加速重复连接，但有重放攻击风险，金融类写操作应禁用或二次校验。

四、HTTP/3 与 HTTP/2 对比（概念）

项 HTTP/2 over TCP HTTP/3 over QUIC
传输 TCP UDP
多路复用 H2 帧共享 TCP 连接 QUIC 流级隔离更好
TLS 传统分层 紧耦合在 QUIC 握手中

HTTP 语义（方法、状态码、首部）仍见 HTTP 一文。
