第七章：MySQL 数据库设计

概念基础：数据库设计是什么、好设计长什么样

数据库设计是把业务模型翻译成表结构的工程——前六章的所有知识在这里汇合成一次综合实战：

  1. 从实体与关系开始：识别业务实体（用户、商品、订单）与它们的关系，一对多用外键字段关联，多对多拆出中间表（如 sys_user_role、sys_role_menu）——这就是第一章「建表即建模」的完整落地。
  2. 工程约定优先于教科书范式：本仓库采用逻辑删除（deleted 字段，数据可追溯）、无外键约束（业务字段关联，利于分库分表与迁移）、统一审计字段（create_time / update_time）三大约定，是互联网业务的主流取舍。
  3. 树形结构用路径换递归：parent_id + ancestors（祖级 ID 路径） 一次查询整棵子树，避免逐层递归，部门、菜单、通用分类都是此法。
  4. 快照与关联的分寸：订单明细把商品名、价格冗余快照进 order_item，商品后续改价不改历史订单——「该快照的快照，该关联的关联」，冗余是有目的的设计而非错误。
  5. 索引随查询而设计：组合索引把 deleted 纳入（如 idx_parent_deleted）配合逻辑删除过滤，唯一键（uk_username、uk_order_no）在数据库层兜底业务唯一性；建表与建索引是一体两面，与第五章的索引原则呼应。

设计约定

约定 说明
无外键 表间通过业务字段（如 user_id、role_id）关联，便于分库分表与数据迁移
逻辑删除 业务表含 deleted（0 否 / 1 是），查询需带 deleted = 0；组合索引常含 deleted
审计字段 多数业务表含 create_time、update_time（自动维护）
树形结构 sys_dept、sys_menu、common_category 使用 parent_id + ancestors（祖级 ID 路径，如 1,2,3）
关联表 sys_user_role、sys_role_menu 无 deleted，用唯一键防重复

常见问题

脚本执行后表已存在

init.sql 对每张表先 DROP TABLE IF EXISTS 再 CREATE，会清空该表数据。生产环境请勿直接全量执行，应使用迁移工具（Flyway/Liquibase）做增量变更。

逻辑删除查询不到数据

MyBatis-Flex 或业务层需统一过滤 deleted = 0；关联表 sys_user_role 等无 deleted，删除关系应物理 DELETE。

订单与商品库存

当前 DDL 未包含库存扣减、支付流水表；goods.stock / goods_sku.sku_stock 需在业务代码中维护一致性。

要点 结论
关系建模 实体拆表，多对多拆中间表（关联表用唯一键防重复、无逻辑删除）
三大约定 逻辑删除 + 无外键 + 审计字段，为分库分表与迁移留余地

第十二章：异步线程池

概念基础：异步线程池是什么、为什么

Spring Boot 默认的 spring.task.execution 与本项目自定义线程池参数分离，避免重复注册；自定义池供 @Async 及按需注入 TaskExecutor 使用（如异步写操作日志）。

  1. 异步（@Async）：把耗时操作（写审计日志、发通知、导出报表）交给后台线程执行，主线程立即返回，提升接口响应速度与吞吐。
  2. 为什么要自定义线程池：Boot 默认池参数保守，且与本工程配置体系脱节；自定义 app.async.executor.* + ThreadPoolTaskExecutor，让核心线程数、队列容量、拒绝策略、关闭策略全部可控。
  3. 线程池的价值：复用线程，避免频繁创建销毁的开销；用有界队列 + 拒绝策略保护系统不被突发流量压垮——本项目用 CallerRunsPolicy 形成背压，队列满时由调用线程兜底执行。
  4. @Async 生效条件：方法必须经 Spring 代理调用，同类自调用不生效；Bean 名 taskExecutor 是 @Async 的默认执行器。
  5. 典型场景：操作审计日志异步落库（见第十章），OperLogRecordService.saveAsync 即走本池。

第十一章：防重提交与接口幂等

概念基础：防重提交与接口幂等是什么、为什么

  1. 重复请求从哪来：用户双击表单、页面刷新 / 回退、网络超时重试，都会让同一业务请求到达多次，导致重复下单、重复扣款。
  2. 防重提交（@RepeatSubmit）：计算请求指纹（类名 + 方法 + URI + Token + 参数 JSON 的 SHA256），在 interval 窗口内发现相同指纹直接拒绝（429），解决「手快双击」类问题。
  3. 接口幂等（@Idempotent）：客户端为「业务唯一」请求携带幂等键 Idempotency-Key，服务端首次成功后缓存结果，重放请求直接返回首次结果——多次调用，效果一致。
  4. 为什么基于 Redis：多实例部署下，指纹与结果必须全局共享；Redis 的 TTL 天然适合做时间窗口与结果缓存（部署见第四章）。
  5. 二者关系：防重是「窗口内拒绝」，幂等是「重放返回原结果」，按业务场景选择或组合使用。

本工程基于 Redis 提供两种注解：

注解 场景 行为
@RepeatSubmit 短时防双击 相同指纹在 interval 内拒绝
@Idempotent 支付/下单 相同幂等键返回首次成功结果

概念基础：AOP 日志与操作审计是什么、为什么

第九章：全局跨域与参数校验

概念基础：全局跨域与参数校验是什么、为什么

  1. 跨域（CORS）：浏览器的同源策略会限制不同源（协议 / 域名 / 端口任一不同）的页面读取响应；CORS 是官方解法——服务器通过 Access-Control-* 响应头声明放行的源，非简单请求会先发 OPTIONS 预检。
  2. 为什么要「全局」配置：跨域是全站横切关注点，在 WebMvcConfiguration（实现 WebMvcConfigurer#addCorsMappings）统一配置 app.cors.* 属性，比逐个 Controller 写 @CrossOrigin 更集中可控、可按环境收窄。
  3. 参数校验（Validation）：基于 Jakarta Bean Validation 注解（@NotBlank、@Email、@Min 等）声明式描述约束，由 spring-boot-starter-validation 在 Controller / Service 入口自动校验，替代散落各处的手写 if。
  4. 失败要统一处理：校验异常统一交给 GlobalExceptionHandler（见上一章），返回 400 + Result，前端拿到一致的错误结构，这也是「统一返回体」链路的自然延伸。
  5. 共同定位：二者都是 API 的入口守卫——把非法请求挡在业务逻辑之前，是接口健壮性与安全性的第一道防线。

第八章：SpringBoot 统一返回体与全局异常

概念基础：统一返回体与全局异常是什么

  1. 统一契约：成功与失败均使用同一 JSON 结构，便于前端统一解析；Result<T> 三字段 code / msg / data。
  2. 两层语义：HTTP 状态码表达协议层语义（400/409/500 等），code 字段表达业务语义（可与 HTTP 一致或自定义）。

  4. 校验联动：@Valid / @Validated 触发的 MethodArgumentNotValidException 与 ConstraintViolationException 同样统一处理为 400。
  5. 模板复用：完整 GlobalExceptionHandler 源码模板见 第五章：Java 全局异常处理：@RestControllerAdvice 与统一 Result；本章描述 springboot 仓库中的落地方式与验证。

概念基础：MyBatis-Flex 与多数据源是什么

  1. ORM 增强：MyBatis-Flex 是 MyBatis 之上的轻量 ORM，提供 IService / ServiceImpl 与分页，低侵入、强调查询性能与 APT 编译期能力。

  5. 通用 @DS 与事务边界见 第六章：Java 动态数据源：@DS 切换与事务边界；Flex API 见 第七章：MyBatis-Flex 入门与代码生成；连接池见 第十三章：数据库连接池：HikariCP与Druid对比与落地。

第四章：SpringBoot 集成 Redis 与缓存

概念基础：Redis 缓存是什么

缓存把热点数据放进内存数据库，用空间换时间，降低数据库压力、缩短响应时间：

  1. 三种接入方式：本项目集成 Spring Data Redis（StringRedisTemplate）、Redisson（分布式对象、Bucket 等）、Spring Cache（@Cacheable，底层为 Redis），按场景选用。
  2. 统一连接层：三者最终都经 Lettuce 连接访问同一个 Redis（见架构图），连接与超时配置集中管理。
  3. TTL 必设：缓存写入务必带过期时间（如探针 120 秒），防止脏数据长期滞留与内存膨胀。
  4. 业务耦合点：防重、幂等、缓存探针均依赖 Redis——防重用 SET NX + TTL，幂等缓存首次成功的 Result JSON。
  5. 测试隔离：单测排除 Redis 自动配置、缓存切换 simple 并注入 Mock Bean，保证无 Redis 也能跑通测试。
