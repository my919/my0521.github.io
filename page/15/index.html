第八章：SPI

概念基础

  1. SPI（Serial Peripheral Interface）是 Motorola 提出的四线同步全双工总线：SCLK / MOSI / MISO / CS，板级高速外设互联的主力。
  2. 主驱时钟：主站产生 SCLK，数据按约定边沿采样；主从的 CPOL/CPHA 模式必须一致（Mode 0~3），这是 SPI 调试最常见的坑。
  3. 片选寻址：没有地址概念，每个从机一根独立 CS 线，多占一根线换取高速度；MISO 未选中时需保持三态。
  4. 为什么快：无地址开销、全双工、时钟可达几十 MHz，Flash、SD 卡、TFT 屏等高带宽外设首选。
  5. 取舍：线数多（每从机 +1 CS）、只适合短 PCB 走线；长距离/多机改用 RS485，少线低速场景可用 I2C，异步调试打印仍用 UART。

二、CPOL / CPHA（模式 0~3）

  • CPOL：空闲时 SCLK 电平（0=低，1=高）。
  • CPHA：第几个边沿采样（0=第一边沿，1=第二边沿）。

主从 模式必须一致（数据手册会写 Mode 0 等）。

三、多从机

  • 独立 CS：每个从机一根 CS，MOSI/MISO/SCLK 共享（MISO 需三态，未选中不高驱）。
  • Daisy Chain：如部分 Shift Register、LED 驱动，数据串行穿过多芯片。

四、典型应用

  • Flash（W25Q）、SD 卡（SPI 模式）、ADC/DAC、TFT 屏、RF 模块（NRF24L01）。
  • 速率常 MHz~ tens of MHz，短 PCB 走线；长距离不如 第六章：RS485。

五、与 I2C

SPI 第七章：I2C
线数 4+（每从机 +CS） 2
速度 通常更快 400k/1M 常见
寻址 硬件 CS 7 位地址
双工 全双工 半双工

异步调试打印仍用 第四章：UART。

本章小结

要点 结论
信号 SCLK/MOSI/MISO/CS 四线，主驱时钟、全双工
模式 CPOL/CPHA 组成 Mode 0~3，主从配置必须一致
寻址 无地址，靠独立 CS 片选；MISO 未选中需三态
速度 无地址开销、全双工，可达几十 MHz，高带宽外设首选
局限 线多、仅短走线；远距离换 RS485，少线换 I2C

第七章：I2C

概念基础

  1. I2C（Inter-Integrated Circuit）是 Philips 发明的两线同步总线：SCL 时钟 + SDA 数据，是板级互联传感器/存储器等外设的事实标准。
  2. 地址寻址多从：每个从设备有 7 位地址（0x00~0x7F），主设备以地址帧寻址——两根线即可挂多个器件，扩展外设几乎不加线。
  3. 开漏 + 上拉：SDA/SCL 均为开漏输出加上拉电阻，天然支持多主仲裁与时钟同步，也决定了速率上限（100k/400k/1M/3.4M）。
  4. 协议机制清晰：START/STOP 条件界定传输，逐字节 ACK/NACK 确认；读操作用重复 START 切换方向。
  5. 取舍：线最少、成本低，EEPROM/RTC/IMU/OLED 全支持；但速率不如 SPI，上拉取值需按总线电容与速率权衡。

先看总线拓扑：

总线拓扑



flowchart TB
  Master[主设备 MCU] --- SCL[SCL 时钟]
  Master --- SDA[SDA 数据]
  SDA --> S1[从设备 地址 0x48]
  SDA --> S2[从设备 地址 0x50]
  SCL --> S1
  SCL --> S2

一、信号与起始/停止

  • 空闲：SDA、SCL 均为高（靠上拉电阻）。
  • START：SCL 高时 SDA 下降沿。
  • STOP：SCL 高时 SDA 上升沿。
  • 数据位：SCL 低时 SDA 变化，SCL 高时采样。

二、7 位地址帧（写）

读操作：写寄存器指针 → 重复 START → 读地址 + 读数据 + NACK + STOP。

三、速率模式

模式 速率
Standard 100 kHz
Fast 400 kHz
Fast Mode Plus 1 MHz
High Speed 3.4 MHz（较少用）

上拉电阻：常见 2.2k~10k（3.3V、总线电容与速率相关）；长电缆或多设备需降低电容、可能用 I2C 缓冲器/扩展器。

四、典型设备

  • EEPROM（24Cxx）、RTC（DS3231）、IMU、OLED 小屏、PMIC、GPIO 扩展（PCF8574）。
  • 同一地址冲突：部分芯片有 ADDR 引脚改地址；否则需不同总线（I2C mux）。

五、与 SPI、UART

总线 线数 速度 特点
I2C 2 + GND 中 多从、地址、开漏
第八章：SPI 4+ 高 全双工、无标准地址
第四章：UART 2 + GND 中 点对点、异步

第九章：CAN 总线：帧结构、多主仲裁与 CAN FD 用于车载/工业现场总线，抗干扰与仲裁不同于 I2C。

本章小结

要点 结论
总线 SCL+SDA 两线同步总线，开漏 + 上拉，支持多主多从
寻址 7 位地址帧寻址，读方向用重复 START 切换
握手 每字节 ACK/NACK 确认；START/STOP 界定传输
速率 标准 100k / 快速 400k / FM+ 1M / HS 3.4M
实务 上拉 2.2k~10k 按速率与电容配置；地址冲突用 ADDR 引脚或 I2C mux

第六章：RS485

概念基础

  1. RS485（TIA/EIA-485） 是差分电气标准：用 A/B 两线电压差表示信号，抗共模干扰强、可达上千米，是工业现场最常用的物理层。
  2. 总线型多机：一条双绞线手拉手（daisy-chain）挂多个节点，配合地址协议实现多机组网；总线两端各接 120Ω 终端电阻。
  3. 半双工：两线制同一时刻只能一个方向发送，收发器需 DE/RE 引脚切换方向。
  4. 只管电气不管语义：RS485 只解决「电信号怎么传」，上层要跑 Modbus RTU 等主从协议才能完成有效通信。
  5. 与 UART 的关系：MCU 的 UART 产生字节流，经 MAX485/SN65HVD 收发器转成差分信号——UART 管逻辑、485 管物理。

先看总线型拓扑：

总线型拓扑

  M[主站] --- BUS[A/B 差分总线]
  S1[从站 1] --- BUS
  S2[从站 2] --- BUS

一、拓扑

  • 半双工：同一时刻只能一个方向发送；需 DE/RE 引脚控制收发器方向。
  • 共模范围：约 -7V ~ +12V，适合工业现场。

二、UART + RS485 收发器

MCU 第四章：UART 接 MAX485/SN65HVD 等：

发送前切换 DE；切换后需等待收发器稳定再发首字节，避免毛刺。

三、与 Modbus RTU

第一章：Modbus RTU 在 **RS485** 上最常见：**主站轮询**、**从站地址 1~247**、**CRC16** 帧尾。

与 第三章：Modbus ASCII 比，RTU 更紧凑、工业现场更常用。

四、对比 RS232

项目 RS232 RS485
信号 单端 差分
距离 短 长
节点数 点对点为主 多机总线
双工 全双工常见 半双工为主

五、布线注意

  • 双绞线、屏蔽层单端接地（现场依规范）。
  • 终端电阻 120Ω 仅在总线两端；中间节点不加。
  • GND 参考：虽为差分，仍建议可靠参考地，避免共模超范围。
  • ESD 与浪涌：户外/电机旁加保护器件。

本章小结

要点 结论
电气 差分（A/B） 传输，共模约 -7V~+12V，抗干扰强、距离长
拓扑 总线型手拉手，两端各接 120Ω 终端电阻，中间节点不加
双工 两线制半双工，发送前切 DE，切后等收发器稳定
组合 UART 控制器 + 485 收发器（MAX485/SN65HVD）
上层协议 最常见搭配 Modbus RTU（主站轮询、从站地址 1~247）

第五章：RS232

概念基础

  1. RS232 是 EIA 定义的串行物理层标准，规定电气电平、信号线与连接器（DB9）——「PC 老式 COM 口」背后的标准。
  2. 负逻辑电平：逻辑 1 是负电压（-5V~-15V），逻辑 0 是正电压（+5V~+15V），与 MCU 的 TTL UART（0/3.3V）完全不同，必须经 MAX232 等芯片做电平转换。
  3. 点对点、单端：一收一发加共地，抗干扰弱、典型距离 < 15m，速率与距离反相关。
  4. 为什么仍要学：工业仪器、老式 PLC、条码枪仍大量保留 DB9 口；PC 侧 USB 转 RS232 线依然是常用调试手段。
  5. 与 UART 的关系：UART 是控制器逻辑，RS232 是物理层电气标准；其上仍可跑 Modbus RTU 或自定义帧协议。

先看典型的 DTE-DCE 连接：

DTE-DCE 连接



flowchart LR
  PC[DTE PC] -->|TXD RXD GND| Conv[USB-RS232 转换]
  Conv --> Dev[DCE 设备]

一、电平与特点

  • 逻辑 1：负电压（如 -5V ~ -15V）
  • 逻辑 0：正电压（如 +5V ~ +15V）
  • 单端：抗干扰弱于 第六章：RS485 差分；距离通常 < 15m（与波特率反相关）。
  • 点对点：多机需额外切换，不像 RS485 总线型。

MCU 侧为 TTL 第四章：UART（0/3.3V），需 MAX232、SP3232 等芯片做电平转换。

二、最小三线连接

交叉连接 TX/RX；不要把 RS232 口直接接 MCU UART 引脚。

三、流控（可选）

信号 作用
RTS/CTS 硬件流控，防缓冲区溢出
DTR/DSR 设备就绪（Modem 时代遗留）
软件流控 XON/XOFF 字符

嵌入式调试常 115200 8N1 无流控。

四、应用场景

  • 工业仪器、老式 PLC、条码枪 DB9 口。
  • USB 转 RS232 dongle 在 PC 上模拟 COM 口。
  • 长距离、多机、抗干扰场景优先 RS485 或 以太网（第二章：Modbus TCP）。

协议层仍可能是 第一章：Modbus RTU 或自定义 ASCII 帧。

本章小结

要点 结论
电平 负逻辑：1 = -5V-15V，0 = +5V+15V，与 TTL 不兼容
拓扑 点对点、单端，典型距离 < 15m，多机换 RS485
连接 最小三线 TXD/RXD/GND，TX/RX 交叉；禁止直连 MCU 引脚
电平转换 MCU TTL UART 经 MAX232/SP3232 接入
定位 老设备/仪器调试口；新设计长距离优先 RS485 或以太网

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 657 阅读时长 ≈ 2 分钟

第四章：UART

概念基础

  1. UART（通用异步收发器）是异步串行通信控制器：只用 TX/RX 两根信号线加共地，不传时钟，收发双方按约定的波特率各自采样。
  2. 异步帧：起始位(0) + 数据位(通常 8) + 可选校验位 + 停止位(1)；空闲为高电平，起始位拉低完成一次同步，数据 LSB 先发。
  3. 为什么无处不在：实现极简、调试直观，日志打印、AT 指令、GPS NMEA、Bootloader 都走 UART，是嵌入式最基础的调试与互联手段。
  4. 只是逻辑层：UART 引脚是 TTL 电平（0/3.3V），接 PC 老串口或工业总线需 MAX232（RS232）、MAX485（RS485） 等收发器转换物理层。
  5. 点对点：无从机地址、无仲裁，多机组网要靠上层协议或改用总线型物理层。

先看最基本的连接形态：

点对点连接



flowchart LR
  MCU1[MCU A TX] -->|RX| MCU2[MCU B RX]
  MCU2 -->|TX| MCU1

一、异步帧结构

  • 空闲：线路高电平。
  • 起始位：拉低，通知接收方开始采样。
  • LSB 先发：数据位从低位到高位。
  • 校验：None / Odd / Even（可选）。
  • 停止位：1 或 2 位高电平，恢复空闲。

二、波特率

常见：9600、115200、921600。收发双方波特率必须一致（误差通常 < 2%）。

三、电平与接口层

层次 说明
TTL UART MCU 引脚 3.3V/5V，直连 USB-TTL 模块
第五章：RS232 ± 电平，PC 老式串口、部分工业设备
第六章：RS485 差分、半双工、多机总线，常经 UART+收发器

UART 指控制器逻辑；对外物理层常加 MAX232、MAX485 等芯片。

四、应用与调试

  • 日志打印、AT 指令（4G/Wi-Fi 模块）、GPS NMEA、Bootloader。
  • Linux：/dev/ttyUSB0，minicom / picocom / screen。
  • 注意：TX 接 RX 交叉；共地 GND 必须连接。

与 第八章：SPI、第七章：I2C 对照：UART 线少、距离短（TTL）、协议简单，无硬件从机地址。

本章小结

要点 结论
本质 两线异步串行控制器，不传时钟，靠约定波特率采样
帧格式 起始位 + 数据位（LSB 先发）+ 可选校验 + 停止位
关键参数 双方波特率必须一致（误差 < 2%），常见 9600/115200
物理层 TTL 引脚直连需共地；上 RS232/RS485 需收发器转换
调试要点 TX/RX 交叉、必须共地；Linux 用 minicom/picocom/screen

第三章：Modbus ASCII

概念基础

  1. Modbus ASCII 是 Modbus 的文本编码变体：每个字节用两个 ASCII 十六进制字符（0-9 A-F）表示，帧以 : 开始、CR LF 结束。
  2. 为什么存在：早期调制解调器/串口终端时代，文本帧人眼可读、可直接粘贴调试，字符间容忍度也比 RTU 严格的 3.5 字符静默宽松。
  3. 校验不同：RTU 用 CRC16，ASCII 用 LRC（8 位求和取补码）——检错能力较弱但实现极简。
  4. 代价：同样数据传输长度约 2 倍、带宽利用率低，新项目工业现场几乎都选 RTU，ASCII 只保留在老设备与维护口。
  5. 同一套 PDU：与 RTU/TCP 的功能码与寄存器语义完全一致，切换链路层不影响上层应用逻辑。

先直观对比两种编码：

与 RTU 对比

一、帧格式

示例（读保持寄存器，概念）：

  • : 起始。
  • 每字节用 两个 ASCII 十六进制字符（0-9 A-F）。
  • CR LF 结束（0x0D 0x0A）。

二、LRC

对 地址到数据末字节 求和（8 位），取二进制补码（256 - sum），再转两个 ASCII 十六进制字符。

RTU 使用 CRC16；ASCII 用 LRC，检错能力较弱但实现简单。

三、与 RTU / TCP

变体 编码 效率 场景
RTU 二进制 高 RS485 主流
ASCII 文本 HEX 低（约 2× 字节） 调试、老设备
第二章：Modbus TCP 二进制 + MBAP 高 以太网

同一 PDU 功能码 语义一致；切换链路层时注意地址与寄存器映射相同。

四、调试

  • 串口终端可直接粘贴 : 帧（若设备支持 ASCII 模式）。
  • 物理层常为 第五章：RS232 或 第六章：RS485 + 第四章：UART。
  • 生产系统优先 RTU 或 TCP，ASCII 多用于维护口。

本章小结

要点 结论
帧格式 : 起、CRLF 止，每字节展开为两个 ASCII HEX 字符
校验 LRC 8 位求和取补码，弱于 RTU 的 CRC16
效率 传输体积约 2 倍，工业新项目首选 RTU
价值 可读可粘贴，适合调试与老设备维护
兼容 PDU 功能码语义与 RTU/TCP 完全一致

第二章：Modbus TCP

概念基础

  1. Modbus TCP 把 Modbus 的主从语义搬到以太网/TCP：报文仍是「功能码 + 数据」，但帧定界交给 TCP、校验交给 TCP 校验和，因此没有 CRC、没有静默时序。
  2. MBAP 头（7 字节）取代 RTU 的「从站地址 + 静默界定」：Transaction ID 让一条连接可区分多个并发事务，Unit ID 负责映射网关后的串口从站。
  3. 默认端口 502：约定俗成；接入即用，可跨交换机、跨网段访问远程设备，无需 485 布线与收发方向切换。
  4. 网关共存：大量存量设备仍是 RTU 串口设备，TCP ↔ RTU 网关完成两者转换，是工业现场新旧系统融合的典型形态。
  5. 边界：明文、无认证，安全只能靠工控内网隔离、VPN、TLS 隧道，绝不能直接暴露公网。

先看典型的连接模型：

TCP 连接模型



flowchart LR
  SCADA[SCADA 主站] -->|TCP :502| PLC[PLC / 网关]
  PLC --> RTU[Modbus RTU 从站 经串口]

一、MBAP 头（7 字节）

字段 长度 说明
Transaction ID 2 事务标识，请求/响应配对
Protocol ID 2 固定 0
Length 2 后续字节数（Unit ID + PDU）
Unit ID 1 设备地址（经网关映射 RTU 从站）

其后为与 第一章：Modbus RTU 相同的 功能码 + 数据（无 CRC）。

响应 MBAP 中 Length 与 Transaction ID 与请求对应。

三、连接模型

  • 单连接多事务：常见一客户端对一 PLC 长连接 502。
  • 并发：多客户端连同一设备需注意 PLC 连接数限制。
  • 与 第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例：不同协议；工业网关可能同时提供 Modbus TCP 与 OPC UA。

四、串口网关

Unit ID 映射 RS485 从站地址；网关内维护 第六章：RS485 轮询时序。

五、安全

  • 502 明文、无认证 → 仅放工控内网或 VPN；勿暴露公网。
  • 现代方案：TLS 隧道、VPN、专用安全网关。
  • 与 第三章：Modbus ASCII 比：TCP 适合跨交换机、远程 SCADA。

要点 结论
帧变化 无 CRC、无静默界定；MBAP 头（7 字节）+ PDU
并发 Transaction ID 支持单连接多事务；留意 PLC 连接数上限
网关 TCP ↔ RTU 网关：Unit ID 映射 485 从站地址与轮询时序

选型 跨网段、远程 SCADA 选 TCP；现场总线仍是 RTU 主流

第一章：Modbus RTU

发表于 2026-05-01 更新于 2026-09-01 分类于 Embedded 本文字数： 766 阅读时长 ≈ 3 分钟

第一章：Modbus RTU

概念基础

  1. Modbus 是 Modicon 于 1979 年为 PLC 设计的应用层主从协议，如今是工业通信最通用的事实标准之一；RTU 是其中「二进制编码 + 异步串口」的变体。
  2. 主从轮询模型：一个主站（PLC/SCADA）按从站地址轮询，从站永不主动上报，只有被寻址才应答——模型简单、时序确定、实现成本低。
  3. 帧结构极简：地址 + 功能码 + 数据 + CRC16，一帧即一次完整的请求/应答；统一的寄存器语义（线圈、保持寄存器等）让不同厂商设备能用同一套报文访问。
  4. 为什么选 RTU：跑在 RS485 差分总线上，一根双绞线可挂多设备、传数百米，抗干扰强、布线便宜，是工业现场最常见组合。
  5. 边界：RTU 只定义数据读写语义，不含认证加密；帧界定靠静默时间而非特殊字符，底层串口由 UART 控制器提供。

理解了定位，先看最典型的主从轮询交互：

主从轮询



sequenceDiagram
  participant M as 主站 PLC
  participant S as 从站 地址 1
  M->>S: 读保持寄存器 FC03
  S-->>M: 数据 + CRC
  M->>S: 写单个寄存器 FC06
  S-->>M: ACK

一、RTU 帧结构

  • 地址 0：广播（从站不应应答）。
  • CRC：对地址到数据末字节计算 Modbus CRC16。

示例（读保持寄存器 0x03）：主站发 01 03 00 00 00 0A C5 CD（含义依上下文解析）。

二、常用功能码

码 名称 说明
0x01 Read Coils 读线圈（位）
0x03 Read Holding Registers 读保持寄存器（16 位）
0x04 Read Input Registers 读输入寄存器
0x06 Write Single Register 写单寄存器
0x10 Write Multiple Registers 写多寄存器

异常应答：功能码 + 0x80，后跟异常码。

三、时序（RTU 特有）

帧间静默 ≥ 3.5 字符时间（与波特率相关），用于帧界定；波特率高时该间隔很短，实现需精确。

  • 115200 下对 MCU 中断延迟更敏感。
  • 半双工 第六章：RS485 需在发送前使能 DE。

四、与其它 Modbus

变体 链路 帧界定
RTU RS485/RS232 静默 + CRC
第三章：Modbus ASCII 串口 : 起 CRLF 止，LRC
第二章：Modbus TCP 以太网 MBAP 头 + 无 CRC

寄存器地址映射（40001 等）在文档与 PDU 偏移间需 减 1 转换，避免 off-by-one。

五、调试

  • Modbus Poll / Slave（Windows）、pymodbus、QModMaster（Linux）。
  • 抓包：串口监听或 RS485 分析仪。
  • 与 第四章：UART 关系：RTU 是应用层协议，底下是异步串口 + 485 收发器。

Modbus 组织：https://modbus.org/

本章小结

要点 结论
协议本质 应用层主从轮询协议，从站只应答、不主动上报
帧结构 地址 + 功能码 + 数据 + CRC16，帧间静默 ≥ 3.5 字符时间
核心功能码 0x01/0x03/0x04 读，0x06/0x10 写；异常应答 = 功能码 + 0x80
物理搭配 半双工 RS485 总线，发送前使能 DE
调试 Modbus Poll/pymodbus/QModMaster + 串口抓包

第四章：数仓分层与数据管道调度

发表于 2026-05-01 更新于 2026-09-01 分类于 BigData 本文字数： 1.5k 阅读时长 ≈ 5 分钟

第四章：数仓分层与数据管道调度

概念基础

  1. 数仓分层的目的是治理复杂度：ODS 贴源、DWD 明细、DIM 维度、DWS 汇总、ADS 应用——每层职责单一，下游依赖上游，坏数据能定位到层。
  2. 批流一体靠统一模型：Spark（第一章：Spark 大数据批处理入门）跑离线重算，Flink（第二章：Flink 流式计算入门）跑实时增量，两边共用口径才能「T+1 准确、实时大致对」互为校验。
  3. Kafka 是管道骨架：CDC 与日志先进 Kafka（第三章：Kafka 大数据数据总线）缓冲解耦，再分流到批/流/OLAP 各消费者。
  4. 调度是数据可靠性核心：Airflow/DolphinScheduler 把「每天 2 点跑批」变成有依赖、可重试、有告警的 DAG，而不是一堆 crontab。
  5. ClickHouse 承接分析层：DWS/ADS 汇总结果落到列存引擎供 BI 查询，见 第三章：ClickHouse 查询与性能调优。

本章聚焦管道编排与分层建模方法论；沙箱无 Airflow/Spark 集群，代码按 Airflow 2.x 官方语法书写未逐条运行验证。

一、分层模型



flowchart LR
  S[(业务库/日志)] -->|CDC/采集| O[ODS 贴源层]
  O --> W[DWD 明细层]
  DIM[(维度表)] --> W
  W --> S2[DWS 汇总层]
  S2 --> A[ADS 应用层]
  A --> BI[BI/报表/API]
层 职责 关键约束
ODS 原样落地，不做加工 保留原始格式；按天分区快照
DWD 清洗、去重、脱敏、拆平明细 一行一件事务/事件；只依赖 ODS
DIM 维度表（用户、商品、地区） 缓慢变化维（SCD2）记录历史
DWS 按主题预聚合（日/用户粒度） 口径唯一，重算成本可控
ADS 面向报表/大屏/接口的最终宽表 只依赖 DWS+DIM，不碰 ODS

分层价值：重复计算下沉、口径收敛（改一处全局生效）、问题定位快（ADS 错 → 查 DWS → 查 DWD）。

二、CDC 采集：业务库变更入仓

ODS 两种落地形态：每天全量快照（简单、可回溯）与增量 upsert（省存储、需主键合并）——中小规模优先全量快照 + 关键表才做增量。

三、Airflow：把批处理编排成 DAG

调度实践要点：

实践 说明
数据就绪探测 用 Sensor 等「源表分区就绪」（/data/ods/dt=2026-05-01/_SUCCESS）再开跑
幂等设计 所有任务以 dt=日期分区 覆盖写，重跑不产生重复
回刷 补数 = 对历史日期重放 DAG；幂等是回刷安全的前提
分区约定 全公司统一 dt/hh 分区字段，下游依赖检查分区存在性
SLA 与告警 任务超过预期时长告警；失败走 IM webhook（见 第五章：系统运维进阶 的日志与监控）

四、批流双跑与一致性

问题 方案
实时与离线口径不一致 统一 DWS 层 SQL 口径，代码同源（或用 Flink 批模式跑离线）
迟到数据 Flink 水位线 + allowed lateness；离线重算兜底
重复写入 Kafka 事务 + 幂等 sink（主键去重），见第三章「精确一次」
大宽表爆炸 ADS 只建高频查询宽表，长尾需求走即席查询

五、数据质量门禁

检查 时机
表行数/波动率 ODS 就绪后
主键唯一、非空 DWD 产出后
口径对账（批 vs 流） ADS 产出后
下游新鲜度 报表侧每天首次访问校验数据日期

本章小结

要点 结论
分层 ODS 贴源 → DWD 明细 → DIM 维度 → DWS 汇总 → ADS 应用；坏数据逐层定位
采集 CDC 入 Kafka；ODS 用「全量快照 + 关键表增量」起步
调度 Airflow DAG + 数据就绪 Sensor + 幂等分区写，重跑回刷才安全
批流 实时求快、离线求准；每日对账，超阈值重算
质量 唯一性/非空率/波动率做成门禁任务，不过检不放行下游

第四章：RAG 与向量检索实战

发表于 2026-05-01 更新于 2026-09-01 分类于 AI 本文字数： 1.3k 阅读时长 ≈ 4 分钟

第四章：RAG 与向量检索实战

概念基础

  1. RAG = 检索增强生成：把私有知识向量化入库，提问时先检索最相关的片段塞进上下文，再让 LLM 作答——不用重训模型就能注入领域知识，是 LLM 落地性价比最高的路线。
  2. Embedding 是语义坐标系：文本被编码为高维向量（如 1024 维），语义相近的文本距离相近；「检索」从关键词匹配升级为最近邻搜索。
  3. 向量库专管 ANN：Milvus/Qdrant/pgvector 用 HNSW 等索引做近似最近邻查询，毫秒级从千万级向量里捞 Top-K；小规模用 Redis/Postgres 也能起步。
  4. 效果好坏在数据管道：切块（chunking）粒度、检索 Top-K、重排序（rerank）三件事对答案质量的影响大于换模型。
  5. 评估要有 ground truth：召回率（该找的找没找到）与答案忠实度（说的对不对）分开评，肉眼抽查不可持续。

本章承接 第三章：LLM 大语言模型基础 的 RAG 概念，落到工程实现。代码按 LangChain 0.3 / OpenAI SDK 官方 API 风格书写（沙箱未装依赖，未逐条运行验证）。

一、RAG 全链路



flowchart LR
  D[文档] --> C[切块 Chunking]
  C --> E[Embedding 向量化]
  E --> V[(向量库)]
  Q[用户提问] --> QE[问题向量化]
  QE --> V
  V --> R[Top-K 检索 + Rerank]
  R --> P[拼装 Prompt]
  P --> LLM[LLM 生成]
  LLM --> A[带引用的答案]

两条管道：

管道 内容 执行时机
离线索引 文档 → 清洗 → 切块 → 向量化 → 入库 文档新增/变更时
在线问答 问题向量化 → 检索 → 拼 Prompt → LLM 每次提问

二、离线索引：切块与向量化

切块经验值：

参数 建议 理由
chunk_size 300~800 字符 太小丢上下文，太大稀释相关性
chunk_overlap 10%~20% 保住跨界句子
元数据 给每块挂 {"source": 文件名, "section": 标题} 答案引用与按来源过滤都靠它

三、在线检索与生成

Prompt 三原则：明确告知「只依据资料」、资料带来源标记（答案可引用）、temperature=0 降低发挥。

四、向量库选型

方案 定位 适用
Qdrant / Milvus 专用向量库，HNSW/量化，十亿级 独立检索服务
pgvector Postgres 扩展 已有 PG、千万级以内（运维最省）
Redis 向量检索 + 缓存一体 热点数据、低延迟
Elasticsearch BM25 + 向量混合检索 已有 ES、关键词+语义混合
FAISS 进程内库 原型、单机实验

五、评估与迭代

调优顺序（从便宜到贵）：

  1. 切块参数：调 chunk_size/separators，对结构化文档用标题感知切块
  2. 检索深度：先取 Top-20 再 rerank 到 Top-4（召回与精排分工）
  3. 混合检索：加 BM25，专治型号、代码、专有名词
  4. 换 Embedding 模型：领域强的换领域微调模型（中文场景 BGE 系列常用）
  5. 最后才动 LLM：检索对了答案基本就对了

本章小结

要点 结论
RAG 本质 检索注入上下文而非重训模型；离线索引 + 在线问答两条管道
切块 300~800 字符 + 重叠 + 标题感知；每块挂 source/section 元数据
检索 向量 ANN 打底；BM25 混合治专有名词；rerank 精排
选型 有 PG 用 pgvector、独立大规模用 Qdrant/Milvus、原型用 FAISS
评估 召回率与忠实度分开评；调优先动切块与检索，最后动模型
