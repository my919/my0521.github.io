Git 版本控制入门

发表于 2026-05-01 分类于 Git 本文字数： 2.4k 阅读时长 ≈ 8 分钟

Git 是分布式版本控制系统，用来记录代码变更、多人协作与回滚历史。下面从「安装与身份 → 建仓库 / 克隆 / 本地 init 后关联远程 → 日常提交流程 → 分支与合并 → 远程与推送 → 忽略文件 → 误提交后回滚远程 → cherry-pick（挑选提交）」顺序写清楚；命令在 Linux / macOS 终端或 Windows 的 Git Bash / PowerShell 中均可使用（路径按你的本机修改）。

4. 协作与分支保护注意

情况 建议
main 多人共用 用 git revert，不要用强推改历史
个人功能分支 可与维护者约定后 reset + --force-with-lease
平台禁止 force push 只能 revert 或在网页端操作

回滚后通知同事 git pull；若曾 revert，后续再「撤销这次 revert」可用 git revert 那次 revert 产生的提交哈希。

九、cherry-pick：把指定提交「摘」到当前分支

git merge 会把另一条分支上的全部差异合进来；若你只想把对方分支上的某几条提交搬到当前分支（例如 hotfix 上修了一个 Bug，要同步到 release，又不想合并整棵分支树），用 git cherry-pick。

4. 常用选项

选项 作用
-x 在提交说明末尾附一行 (cherry picked from commit …)，便于审计、追溯来源
-n / --no-commit 只应用补丁到暂存区 / 工作区，不自动提交；可连续挑多条再一次性 commit（类似手工 squash）

5. 与 merge 的取舍（简要）

需求 更合适
需要对方分支当前全部内容 git merge
只要个别提交、保持当前分支历史线性感 git cherry-pick

若在 main 上 cherry-pick 了已在功能分支合并过的同一补丁，可能产生重复改动或冲突，需团队约定「以哪条分支为准」。

十、小结

场景 常用命令
安装验证 git --version
身份配置 git config --global user.name / user.email
新建仓库 git init
本地 init 后连远程 git remote add origin <url> → git add / commit → git push -u origin main
克隆 git clone <url>
提交 git add → git commit -m
分支 git switch -c / git merge
远程 git remote add → git push -u
同步 git pull
忽略文件 编辑 .gitignore
远程回滚（安全） git revert <hash> → git push
远程回滚（改历史） git reset --hard <hash> → git push --force-with-lease
挑选提交 git cherry-pick <hash>；冲突后 --continue / --abort

更高级的主题（rebase、子模块、大文件 LFS 等）可在熟练上述流程后，按 Pro Git 中文版 与团队规范继续深入。
