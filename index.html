RocketMQ

发表于 2026-05-17 更新于 2026-05-24 分类于 SpringCloud 本文字数： 662 阅读时长 ≈ 2 分钟

概述

RocketMQ 在 Spring Cloud Alibaba 2025.1.0.0 中通过 spring-cloud-starter-stream-rocketmq 对接 Spring Cloud Stream（函数式 StreamBridge / Consumer），BOM 管理客户端 5.3.1。

本仓库（cloud）当前未集成 RocketMQ。订单与库存为 同步 Feign + Seata 链路，见 订单下单与库存扣减.md。本文供异步解耦、事件驱动扩展参考。

  B[Broker]
  C[Consumer 服务]
  P -->|发送| B
  B --> NS
  C -->|订阅| B

RocketMQ Client 5.3.1（BOM） 未引入
NameServer 5.3.x 与客户端同主版本 需自建
Spring Cloud Stream 随 Cloud 2025.1.0 未使用

说明：2025.x 使用函数式绑定；勿使用已废弃的 @EnableBinding / @StreamListener。

与 Nacos、Seata 的关系

  • Nacos：仅服务注册；Topic/Group 在 RocketMQ 运维侧管理，DataId 可存 name-server 地址。
  • Seata：异步消息场景需单独设计幂等与补偿，不能照搬当前 POST /order/place 同步全局事务。
  • Sentinel：可对 Stream 绑定名配置流控（需额外规则配置）。

  4. RocketMQ Dashboard 或 mqadmin 查看堆积。

常见问题

Q：本仓库下单为何不用 MQ？
A：示例侧重 Seata 跨服务一致性；MQ 适合异步通知、削峰，需另建消费端与幂等表。

Q：Boot 4 能否用旧版 RocketMQ starter？
A：SCA 2025.1.0.0 起已适配 Boot 4，须用 BOM 2025.1.0.0，勿混旧 SCA。

Q：K8s 内 NameServer 地址怎么写？
A：使用 Service DNS，如 rmq-namesrv.<namespace>.svc.cluster.local:9876，通过环境变量注入。

Dubbo

发表于 2026-05-17 更新于 2026-05-24 分类于 SpringCloud 本文字数： 718 阅读时长 ≈ 2 分钟

概述

Apache Dubbo 是 Java RPC 与服务治理框架，通过注册中心发现 Provider，支持 Triple（tri）、经典 dubbo 协议等。与 HTTP + OpenFeign 相比，更适合高频、低延迟的内部调用。

本仓库（cloud）当前未集成 Dubbo。服务间调用使用 OpenFeign（如 cloud-order → cloud-stock），注册发现使用 Nacos，见 订单下单与库存扣减.md、集成Nacos.md。本文供与 SCA 同栈 时扩展参考。

架构说明



flowchart LR
  Consumer[Consumer 应用]
  Registry[(Nacos)]
  Provider[Provider 应用]
  Consumer -->|订阅| Registry
  Provider -->|注册| Registry
  Consumer -->|RPC tri/dubbo| Provider

前置条件

项 建议 说明
JDK 17+（本仓库为 21）
Nacos 与 SCA 2025.1.0.0 对齐的 3.1.x Server 见 集成Nacos.md
Dubbo BOM 3.3.x（如 3.3.6，以 Central 为准） 独立于 SCA 发行节奏
本仓库 — 无 dubbo-spring-boot-starter 依赖

若在本仓库旁路集成（步骤概要）

1. 父 POM 增加 dubbo-bom

2. 子模块依赖

执行 mvn dependency:tree 检查与 Nacos Client 3.1.1 无冲突。

3. 配置示意（勿与 cloud-order 现有 Feign 混用同一接口除非刻意迁移）

  • @DubboService：在 Provider（如 stock）暴露接口。
  • @DubboReference：在 Consumer（如 order）注入代理。

注意：registry.address 须与 Spring Cloud 使用的 同一 Nacos 集群；namespace、group 按 Dubbo 文档配置。

配置说明（集成后常用项）

配置项 说明 示例

dubbo.registry.address 注册中心 nacos://192.168.1.22:30010
dubbo.protocol.name 协议 tri
dubbo.protocol.port 端口，-1 自增 -1
dubbo.consumer.timeout 调用超时 ms 3000

与 OpenFeign 选型

维度 OpenFeign（本仓库） Dubbo
协议 HTTP/JSON 二进制 RPC / Triple
与 Gateway 易统一 REST 通常内部直连
学习成本 低 需接口 jar、协议约定
适用 BFF、对外 REST 核心域高频调用

迁移下单链路前需评估：Gateway 路由、Swagger、Seata 全局事务 与 Dubbo 过滤器的组合，建议单独分支验证。

验证（独立 Demo）

  1. 按 Dubbo 快速开始 起 Provider/Consumer。
  2. Nacos 控制台除 Spring Cloud 服务外，可见 Dubbo 注册元数据。
  3. 压测对比 Feign 与 Dubbo 延迟（本仓库无现成对比脚本）。

常见问题

Q：本仓库能否同时 Feign + Dubbo？
A：技术上可以分接口使用，但同一业务链路易维护成本高；未在 cloud 中验证。

Q：Dubbo 与 Seata？
A：需按 Dubbo + Seata 官方组合配置事务传播；当前 cloud 的 @GlobalTransactional 基于 Feign。

Q：Nacos 地址用 30010 还是 8848？
A：与 Spring Cloud 一致：对外 NodePort 用 30010；本地 Docker 用 8848。

订单下单与库存扣减

发表于 2026-05-17 更新于 2026-05-24 分类于 SpringCloud 本文字数： 619 阅读时长 ≈ 2 分钟

概述

核心链路：下单 POST /order/place（cloud-order）→ OpenFeign → 扣库存 POST /stock/goods/deduct（cloud-stock）。成功时写入 t_order 并减少 goods.stock；失败时由 Seata 全局事务 回滚（默认开启）。测试数据见 sql/test-data-goods.sql。

流程



sequenceDiagram
  participant C as Client
  participant G as Gateway
  participant O as cloud-order
  participant S as cloud-stock
  participant DBo as DB order
  participant DBs as DB stock

  C->>G: POST /order/place
  G->>O: 转发
  O->>O: @GlobalTransactional
  O->>DBo: INSERT t_order
  O->>S: Feign deductGoods
  S->>DBs: UPDATE goods SET stock
  alt stock OK
    O-->>C: code 0
  else stock不足
    S-->>O: 业务异常
    O->>O: 全局 rollback
    O-->>C: code 1
  end

常见问题

Q：PowerShell 里 curl 报 400 或 JSON 错误？
A：使用 curl.exe 或 -d "@文件"；勿用 curl 别名；复杂 JSON 用 Invoke-RestMethod + 文件读入。

Q：GET /order/place 报错？
A：place 仅支持 POST。

Q：回滚后 order 表仍有脏数据？
A：查 Seata 是否启用、TC 是否连通、undo_log 是否已建；看 order 日志是否 commit 而非 rollback。

Q：Feign 超时导致不确定状态？

常见问题

Q：控制台看不到客户端？
A：检查 SENTINEL_DASHBOARD 是否为 30012；防火墙放行；客户端是否排除 simple-http 并使用 netty-http；是否已有流量触发 Sentinel。

集成Seata

发表于 2026-05-17 更新于 2026-05-24 分类于 SpringCloud 本文字数： 1k 阅读时长 ≈ 3 分钟

概述

Apache Seata 在本项目中以 AT 模式 协调 cloud-order（TM）与 cloud-stock（RM）的跨库事务。默认 开启（SEATA_ENABLED 默认 true），TC 地址 192.168.1.22:30014。与 dynamic-datasource 联用时关闭自动数据源代理，改由 spring.datasource.dynamic.seata: true 接入。

架构



sequenceDiagram
  participant TM as cloud-order
  participant TC as Seata TC :30014
  participant RM as cloud-stock
  participant DB1 as MySQL order
  participant DB2 as MySQL stock

  TM->>TC: begin(xid)
  TM->>DB1: INSERT order (branch)
  TM->>RM: Feign deduct
  RM->>DB2: UPDATE goods (branch)
  alt 成功
    TM->>TC: commit
    TC->>DB1: commit branch
    TC->>DB2: commit branch
  else 失败
    TM->>TC: rollback
    TC->>DB1: undo
    TC->>DB2: undo（若有 UPDATE）
  end

模块 Seata

cloud-stock 是（参与分支）
cloud-user / cloud-app / cloud-gateway 否

  3. 修改 Nacos 中 application-datasource.yml 后重启或依赖 refresh 策略验证是否生效。

常见问题

Q：启动报必须配置 spring.config.import nacos？
A：2025.1 强制检查。在对应 profile 的 yml 增加 optional:nacos:application.yml，或按官方说明设置 spring.cloud.nacos.config.import-check.enabled=false（不推荐）。

Q：Nacos 里 Seata 仍是 false，本地 yml 已 true？
A：Nacos 后加载会覆盖。在 application-dev.yml 末尾显式 seata.enabled: true，或更新 Nacos DataId application-seata.yml（模板见 config/nacos-application-seata.yml）。

Q：test 与 prod 和 dev 有何不同？
A：结构相同，仅 application-test.yml / application-prod.yml 中 Nacos 地址、账号可按环境替换；集成测试可用 H2 + seata.enabled=false（见 cloud-order 测试配置）。
