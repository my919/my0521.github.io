UV项目开发添加pre-commit

发表于 2026-05-01 分类于 Python 本文字数： 956 阅读时长 ≈ 3 分钟

pre-commit 会在 git commit 前按 .pre-commit-config.yaml 里从上到下的顺序依次执行钩子，适合把「轻量修复 → Lint/格式 → 类型检查 → 测试」串成前置流水线。本文在 uv 项目中安装 pre-commit，并用 local + uv run 调用与 uv.lock 一致的 Ruff、BasedPyright（与 Pyright 配置兼容）、pytest。假定仓库已用 Git 管理；初始化见《UV从0到1创建项目》，各工具单独说明见《UV项目开发添加Ruff》《UV项目开发添加Pyright》《UV项目开发添加Pytest》。命令默认在项目根目录执行。

一、安装 pre-commit 与前置工具

1. 开发依赖（一次装齐）

提交前若要跑 Ruff / BasedPyright / pytest，需先作为开发依赖安装（若已装可跳过对应包）：

  • Ruff：Lint 与格式化（见《UV项目开发添加Ruff》）。
  • BasedPyright：静态类型检查（见《UV项目开发添加Pyright》）。
  • pytest：单元测试（见《UV项目开发添加Pytest》）。

2. 确认 pre-commit

二、添加配置文件

1. 新建 .pre-commit-config.yaml（含 Ruff、Pyright、pytest 前置链）

在项目根创建 .pre-commit-config.yaml。下面示例顺序为：通用清理 → Ruff → BasedPyright → pytest（可按团队习惯删减或调整顺序）。

说明：

  • pre-commit-hooks 的 rev：须与 Releases 上 tag 一致，文中为示例，可用 uv run pre-commit autoupdate 或手动更新。
  • Ruff：local + uv run，版本与 uv.lock 中 ruff 完全一致；pass_filenames: true 时仅对暂存 .py / .pyi 跑 check --fix 与 format。建议顺序为先 ruff check --fix 再 ruff format（与常见习惯一致）。若某次提交未包含 Python 文件，这两个钩子会被跳过。
  • BasedPyright：pass_filenames: true 时把暂存路径传给 uv run basedpyright（需与 pyproject.toml 里 [tool.pyright] 的 include 等不矛盾）；若要整仓与 CI 一致可改为 pass_filenames: false。
  • pytest：示例为 pass_filenames: false，每次 uv run pytest（范围由 pyproject.toml 中 testpaths 等决定）；若需减负可改为 pass_filenames: true 并加 files: ^tests/ 等。

2. 与 uv.lock 对齐

Ruff、BasedPyright、pytest 均通过 uv run 调用，与本地及 CI 的 uv sync 结果一致；仅 pre-commit-hooks 仍由 pre-commit 按 rev 拉取，与 Python 工具链版本无关。

  • 若你发布库，在包根放置空文件 py.typed（PEP 561），并对公共 API 逐步补类型。

一、nvm 是什么

  • 作用：从源码或官方预编译包拉取 Node，把各版本隔离在用户目录下，通过 nvm use 切换当前终端使用的 node / npm。

    1. 使用 nvm-windows（命令与 nvm-sh 接近但不完全相同，安装包在 Releases 下载）；
    2. 使用 WSL，在 Linux 子系统里按本文 二、三 安装 nvm-sh；
    3. 使用 fnm、Volta 等跨平台工具（非 nvm，但可管理多版本 Node）。
  • 国内镜像：可在安装 Node 前设置 NVM_NODEJS_ORG_MIRROR（具体变量名与地址以当前 nvm 文档为准），以加速 nvm install。
  • 与系统自带 node 冲突：若曾用包管理器安装过 node，which node 可能仍指向旧路径；确保 nvm use 后 PATH 中 nvm 的 shim 在前，或卸载系统级 Node 后再试。
