Docker 部署 RocketMQ

发表于 2026-05-01 更新于 2026-05-04 分类于 MQ 本文字数： 1.7k 阅读时长 ≈ 6 分钟

Apache RocketMQ 在 Docker 中至少需要 NameServer 与 Broker 两个进程（常见为两个容器）。下文给出镜像选型、三条命令起最小栈、Compose 一键起栈与一份多文档 K8s 清单；Broker 监听与 brokerIP1 等请按部署环境调整，勿把生产敏感配置提交进仓库。

一、前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

满足即可，与宿主机操作系统无关。

二、RocketMQ 镜像选择

1. 官方镜像（推荐）

  • 仓库：apache/rocketmq（Docker Hub：https://hub.docker.com/r/apache/rocketmq/tags），与 Apache RocketMQ 发行版本对应。
  • 常用标签：如 apache/rocketmq:5.3.2（下文以此为例；升级时请同时核对容器内 ROCKETMQ_HOME 下 conf 路径是否随版本变化）。
  • 生产建议：固定补丁级标签或记录 digest，避免 latest 漂移。

2. 角色与端口（开发常用）

组件 说明 常见映射端口（示例）
NameServer 路由注册与发现 9876
Broker 消息存储与转发 10909、10911、10912 等（与 broker.conf / 启动参数有关）
Proxy（5.x 可选） gRPC 接入等（官方 Docker 快速入门常与 --enable-proxy 一并启用） 8080、8081 等

3. 与官方「Broker + Proxy」快速入门的关系

Apache 文档推荐挂载 broker.conf 并执行 mqbroker --enable-proxy（见 Run RocketMQ in Docker）。下文 Compose 提供带 Proxy 的完整示例；若仅需经典 Remoting 客户端，可将 Broker 的 command 改为 sh mqbroker -n <namesrv>:9876 并去掉 Proxy 相关端口（需自行验证与客户端版本匹配）。

4. 资源与持久化

Broker 磁盘与堆内存占用随主题、队列与流量增长较快；Compose 与 K8s 中为 Broker 数据目录挂载卷，并酌情提高 limits。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式跑 Apache RocketMQ，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 RocketMQ 一键部署：由面板编排 NameServer、Broker（及上架版本若含的 Proxy）与数据卷、端口。与下文 docker / Compose / K8s** 中的 **broker.conf**、**NAMESRV_ADDR**、**brokerIP1` 与端口映射对齐或排障时，自 # 三 起各节仍可作对照。适合单台 VPS、家庭服务器等场景。
