TypeScript

发表于 2026-05-01 更新于 2026-05-31 分类于 Node 本文字数： 413 阅读时长 ≈ 1 分钟

TypeScript 是 JavaScript 的超集：在 ECMAScript 之上增加静态类型与编译期检查，编译为可在 Node 与浏览器运行的 JS。下面从「为何使用 → 基本类型与接口 → 泛型与工具类型 → 模块与配置 → 与 Node / 前端工程的关系」顺序写清楚。

一、为何使用 TypeScript

收益 说明
早期发现错误 类型不匹配、属性拼写在编译期报错
IDE 体验 跳转、重构、补全更可靠
大型项目可维护 接口与类型即文档，跨团队协作成本更低
渐进式采用 allowJs、// @ts-check 可逐步迁移

与纯 JS：运行时行为一致；类型在 tsc 或 esbuild/swc 链路中被擦除。

二、基本类型与接口

  • 联合类型：string | number
  • 字面量类型：'GET' | 'POST'
  • 类型别名：type Id = string | number

三、泛型与工具类型

常用内置工具类型：Partial、Required、Pick、Omit、Record、ReturnType。

四、tsconfig 要点

  • strict: true：启用 strictNullChecks 等，推荐新项目打开。
  • module: NodeNext：与 Node ESM/CJS 互操作对齐（Node 18+ 常见）。

五、与工程栈的关系

  • Node 后端：配合 Express / Fastify / NestJS，类型定义包 @types/node。
  • 前端：VUE3 + Vite 默认 TS 模板；vue-tsc 做类型检查。
  • 构建：tsc --noEmit 仅检查；打包可用 Vite / esbuild 更快转译。

Node 版本管理见 Node-nvm。

官方手册：https://www.typescriptlang.org/docs/
