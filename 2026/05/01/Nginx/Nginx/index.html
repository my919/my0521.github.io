Nginx

概念基础：Nginx 是什么/为什么

  1. 高性能 Web 服务器：Nginx 采用事件驱动、异步非阻塞架构，单机可承载数万并发连接，资源占用远低于传统的进程/线程模型。
  2. 反向代理与负载均衡：作为系统入口网关把请求转发给后端多实例（upstream），支持轮询、ip_hash、least_conn 等策略，是微服务架构标配。
  3. 静态资源服务：托管前端构建产物（dist）高效稳定，配合 try_files 无缝支持 SPA 的 history 路由。
  4. TLS 终结：在 Nginx 层统一卸载 HTTPS，后端走明文 HTTP，证书的申请与续期集中在一处管理。
  5. 模块化生态：限流、缓存、重写等能力开箱即用，也是 K8s Ingress Controller 的主流实现之一。

一、常见角色

角色 说明
静态文件 托管 HTML/CSS/JS（如 第二章：Vite 工程化构建与部署 构建的 dist）
反向代理 将 /api 转发到后端 Spring Boot / Node
负载均衡 upstream 多实例 round-robin、ip_hash、least_conn
TLS 终结 证书在 Nginx 卸载，后端走 HTTP

底层基于 第二章：HTTP 详解：报文、方法、版本与 curl/nc 示例 语义；HTTP/2 可在 listen 443 ssl http2 启用。

二、最小静态站点

try_files 最后一项 /index.html 用于 SPA（第一章：Vue 3 核心概念与组件开发 history 路由）。

三、反向代理

  • proxy_pass 末尾 / 是否带，影响 URI 拼接规则。
  • WebSocket：需 proxy_http_version 1.1、Upgrade / Connection 头，见 第十一章：WebSocket 详解：握手、帧与 Python 示例。

四、HTTPS（概念）

证书可用 Let’s Encrypt（certbot） 自动续期；密码学背景见 第一章：OpenSSL 命令行入门与常用操作总览。

五、安装与运维

  • 限流：limit_req_zone、limit_conn_zone
  • 缓存：proxy_cache 减轻后端压力
  • 与 K8s：Ingress Controller 常用 Nginx 实现

官方文档：https://nginx.org/en/docs/

本章小结

要点 结论
静态站点 root + try_files ... /index.html 托管 dist 并兼容 SPA 路由
反向代理 upstream + proxy_pass，转发时补齐 X-Real-IP / X-Forwarded-For 等头
HTTPS listen 443 ssl 挂证书，certbot 自动续期，密码学细节见 OpenSSL 篇
运维三板斧 nginx -t 验配置、systemctl reload 平滑生效、access/error 日志排障
进阶能力 limit_req 限流、proxy_cache 缓存、Ingress Controller 接入 K8s
