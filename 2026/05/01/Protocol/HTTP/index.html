HTTP 详解：报文、方法、版本与 curl/nc 示例

发表于 2026-05-01 更新于 2026-05-31 分类于 Protocol 本文字数： 699 阅读时长 ≈ 2 分钟

HTTP（Hypertext Transfer Protocol）是 Web 的应用层协议：基于请求 / 响应模型，在语义层使用方法、URI、首部与可选正文表达操作。下面从「无状态与资源模型 → 报文结构原理 → 方法与幂等 → 状态码 → HTTP/1.1 与 HTTP/2 → curl 与原始报文示例」顺序写清楚；传输层默认依赖 TCP，安全传输见 HTTPS，全双工见 WebSocket，HTTP/3 见 QUIC。

请求响应模型



sequenceDiagram
  participant C as Client

  C->>S: HTTP Request 方法 URI 首部
  S->>S: 路由 / 业务处理

一、无状态与资源模型（原理）

HTTP 本身无状态：服务器默认不记住「上一次请求」；会话常靠 Cookie、Token、服务端会话存储实现。REST 风格强调用 URI 表示资源，用 HTTP 方法表达操作（与 RPC 风格对照）。

二、报文结构（作用）

1. 请求

  • 请求行：方法、请求目标（路径或绝对 URI）、版本。
  • 首部：Host 在 HTTP/1.1 中语义必填；Content-Length / Transfer-Encoding: chunked 控制正文边界。

2. 响应

三、常用方法与幂等（原理）

方法 典型语义 幂等
GET 读取资源 是
POST 创建 / 提交 否
PUT 整体替换 是
PATCH 部分更新 视实现
DELETE 删除 是
HEAD 同 GET 无正文 是
OPTIONS 探测支持的方法 是

幂等：多次执行相同请求不应带来额外副作用（仍可能每次返回相同结果）。

四、状态码（分类）

范围 含义 例
2xx 成功 200、201、204
3xx 重定向 301、302、304
4xx 客户端错误 400、401、403、404
5xx 服务器错误 500、502、503

五、HTTP/1.1 与 HTTP/2（演进）

  • HTTP/1.1（RFC 9112）：文本形态；Keep-Alive 复用连接；队头阻塞限制并发效率。
  • HTTP/2（RFC 9113）：二进制帧；单连接多路复用；HPACK 压缩首部；浏览器场景几乎总与 TLS 同用。
  • HTTP/3（RFC 9114）：基于 QUIC（UDP）。
