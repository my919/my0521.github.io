UDP 协议详解：数据报语义、MTU 与示例代码

发表于 2026-05-01 更新于 2026-05-04 分类于 Protocol 本文字数： 673 阅读时长 ≈ 2 分钟

UDP（User Datagram Protocol）在 IP 之上提供无连接的**数据报（datagram）**服务：不保证送达、不保证顺序、不维护连接状态，协议头开销小。下面从「设计目标 → UDP 首部与校验和 → 报文边界与 MTU → 典型应用场景 → 与 TCP/QUIC 对比 → 编程与 ping 示例」顺序写清楚。

一、设计目标与作用

1. 解决什么问题

  • 低延迟：无握手、无连接状态机，首包即可发数据。
  • 保留报文边界：一次 sendto 对应一个 UDP 数据报；对端 recvfrom 通常一次收到完整数据报（受缓冲区限制）。
  • 实现简单：适合 DNS、实时音视频、指标上报；可靠性由应用或 QUIC 等在 UDP 之上补充。

2. 与 TCP 的本质差异

维度 UDP TCP
连接 无 有
交付 尽力，可能丢、乱序 可靠有序（重传隐藏丢包）
语义 保留消息边界 字节流（无消息边界）

二、UDP 首部与校验和（原理）

UDP 首部固定 8 字节：源端口、目的端口、长度、校验和。IPv6 下 UDP 校验和必填；IPv4 允许为 0（表示未使用校验和，实践中少见）。校验覆盖伪首部（含 IP 地址与协议号）+ UDP 首部 + 数据，用于检测传输错误。

三、MTU 与分片（为何要注意报文长度）

以太网常见 MTU 1500，扣掉 IP 首部后 UDP 载荷不宜过大，否则触发 IP 分片：任一片丢失常导致整组重组失败，丢包代价被放大。应用层常将 UDP 报文控制在 1200 字节左右以下（穿越未知路径更稳），或自行分片与重传。

四、典型应用

应用 说明
DNS 传统 UDP/53；响应过大时回退 TCP
实时音视频 丢旧帧比重传更有意义
QUIC / HTTP/3 在 UDP 上重建可靠与加密

六、小结
