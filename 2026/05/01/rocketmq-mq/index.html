RocketMQ 消息中间件入门

发表于 2026-05-01 更新于 2026-05-31 分类于 MQ 本文字数： 469 阅读时长 ≈ 2 分钟

Apache RocketMQ 是阿里开源后捐赠的分布式消息中间件：支持顺序消息、延迟消息、事务消息、死信队列，在国内电商与微服务场景广泛使用。本文侧重 MQ 通用概念；Spring Cloud Stream 集成见 Spring Cloud 集成 RocketMQ。

架构



flowchart TB
  P[Producer] --> B[Broker Master]
  B --> NS[NameServer 路由]
  C[Consumer Group] --> B
  NS -.-> P
  NS -.-> C

一、架构组件

组件 作用
NameServer 路由注册中心，轻量、无状态
Broker 存储与转发，分 Master / Slave
Producer 发送消息
Consumer 拉取消息，Push 底层为长轮询

客户端通过 NameServer 发现 Broker 地址。

二、Topic 与 Queue

  • Topic：逻辑分类。
  • Message Queue：Topic 下分片（类似 Kafka 分区，语义不同）。
  • Tag / Key：二级过滤与索引。

三、消费模型

模式 说明
CLUSTERING 同组负载均衡，一条消息只被一个实例消费
BROADCASTING 组内每实例全量接收
重试 / DLQ 消费失败进入重试队列，超限进死信

四、顺序、延迟与事务

1. 顺序消息

同一 MessageQueue 内 FIFO；发送端按 orderId 等 sharding key 固定路由。

2. 延迟消息

内置延迟级别（1s、5s、1m…），适合订单超时关闭。

3. 事务消息

Half 消息 + 本地事务 + 回查；与 Seata 同步事务可对照选型（见 cloud 当前 Feign + Seata 链路）。

五、与 Kafka 的对照

场景 更常选
日志、CDC、流计算生态 Kafka 消息中间件入门
电商订单、定时、事务消息 RocketMQ
Spring Cloud Alibaba Spring Cloud 集成 RocketMQ

六、部署与运维

Docker：RocketMQ-Docker。局域网见 服务（NameServer :30876、Dashboard :30877）。

项 注意
磁盘 CommitLog 顺序写，监控刷盘与磁盘
主从 Master 故障切换策略依版本（DLedger 等）
版本 客户端与 Broker 主版本对齐

官方文档：https://rocketmq.apache.org/docs/
