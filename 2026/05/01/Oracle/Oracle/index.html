Oracle

概念基础：Oracle 是什么/为什么

  1. 企业级关系型数据库：Oracle Database 是老牌商业 RDBMS，在银行、电信、政务等对稳定性、安全合规与厂商支持要求高的核心系统中长期占主导地位。
  2. 实例与数据库分离：Instance（内存 SGA + 后台进程）挂载并打开 Database（物理文件集合），多实例可共享访问同一套库（即 RAC）。
  3. 逻辑存储分层：数据组织在表空间（SYSTEM / SYSAUX / USERS / TEMP / UNDO）中，向下再划分为段、区、块。
  4. 高可用与容灾：RAC 多节点共享存储集群、Data Guard 主备容灾，配合 RMAN 备份恢复构成企业级方案。
  5. PL/SQL 过程化扩展：存储过程、包、触发器可在库内实现复杂业务逻辑，减少应用与数据库之间的往返。

一、架构概念

1. 实例与数据库

  • Database：物理文件集合（数据文件、控制文件、重做日志）。
  • Instance：内存结构（SGA）+ 后台进程（PMON、SMON、DBWn、LGWR 等），挂载并打开数据库。
  • Schema：用户拥有的对象集合（表、视图、过程等），常口语中与「用户」混用。

2. 连接方式

  • 监听器（Listener）：客户端通过 HOST:PORT/SERVICE_NAME 或 SID 连接。
  • 常用客户端：SQL*Plus、SQL Developer、JDBC（jdbc:oracle:thin:@//host:1521/orclpdb）。

二、表空间与存储

概念 说明
表空间（Tablespace） 逻辑存储单元，对应一组数据文件
SYSTEM / SYSAUX 数据字典与辅助组件，勿随意放业务表
USERS 常见默认用户表空间
TEMP 排序、哈希连接等临时段
UNDO 多版本读一致性（类似 MVCC 的 undo）

四、与开源数据库的对照

维度 Oracle MySQL / PostgreSQL
许可 商业（含 Express 等免费版限制） 开源为主
优化器 成熟 CBO，绑定变量与执行计划管理丰富 各版本持续演进
集群 RAC、Data Guard 等企业方案 主从、Patroni、Group Replication 等
适用 存量 Oracle 核心、合规与厂商支持 互联网、云原生、成本敏感

五、运维要点

  • 备份恢复：RMAN 全量/增量、归档模式（ARCHIVELOG）决定能否时点恢复。
  • 补丁与版本：LTS 与 Extended Support 周期需与采购对齐。
  • 字符集：建库时 AL32UTF8 为常见选择，后期修改成本高。
  • 连接池：应用侧控制会话数，避免耗尽 processes / sessions。

本地学习与生产部署请使用官方文档与许可范围内的安装介质：https://docs.oracle.com/en/database/

本章小结

要点 结论
体系结构 Instance（SGA + 后台进程）打开 Database（物理文件），Schema 隶属于用户
存储管理 业务表放 USERS 等业务表空间，UNDO/TEMP 各司其职
SQL 与 PL/SQL 12c+ 用 FETCH 分页；复杂逻辑可用存储过程/包下沉库内
高可用 RAC 横向扩展 + Data Guard 容灾 + RMAN 备份恢复
运维红线 建库定好字符集 AL32UTF8，连接数靠连接池控制，补丁周期与采购对齐
