Flink

发表于 2026-05-01 更新于 2026-05-31 分类于 BigData 本文字数： 424 阅读时长 ≈ 1 分钟

Apache Flink 是流优先的分布式计算引擎：事件时间、Watermark、状态与精确一次语义，适合实时风控、大屏指标、CEP 等低延迟场景。下面从「DataStream API → 时间与窗口 → 状态与 Checkpoint → Flink SQL → 与 Spark/Kafka 的关系」顺序写清楚。

流处理数据流



flowchart LR
  K[Kafka Source] --> Map[map/filter]
  Map --> Key[keyBy]
  Key --> Win[Window + Watermark]
  Win --> Sink[Sink JDBC/ES]
  Win -.-> CP[Checkpoint 状态快照]

一、编程模型

  • Transformation：map/filter/keyBy/window 等。
  • Source / Sink：Kafka、JDBC、文件系统、Pulsar 等连接器。

二、事件时间与窗口

概念 说明
Processing Time 算子机器本地时钟
Event Time 数据自带业务时间戳
Watermark 衡量事件时间进度，触发窗口计算
Window Tumbling、Sliding、Session

乱序数据需 Watermark 延迟 与 allowedLateness 平衡准确性与延迟。

三、状态与 Checkpoint

  • Keyed State：与 keyBy 绑定，如 ValueState、ListState。
  • Checkpoint：异步分布式快照，配合 Kafka 两阶段提交 实现 端到端 exactly-once（依 Sink 支持）。
  • Savepoint：手动一致性快照，用于升级与扩缩容。

四、Flink SQL

Table API / SQL 与 DataStream 可互转；CDC（Flink CDC）常用于同步 MySQL 到数仓或 Kafka。

五、与 Spark 选型

需求 倾向
超大离线批、ML 生态 Spark
毫秒~秒级实时、复杂事件处理 Flink
消息入口 Kafka 消息中间件入门

官方文档：https://nightlies.apache.org/flink/flink-docs-stable/
