Docker 部署 PostgreSQL

发表于 2026-05-01 更新于 2026-05-03 分类于 PostgreSQL 本文字数： 1.4k 阅读时长 ≈ 5 分钟

在 Docker 中运行 PostgreSQL，适合本地开发、与 Compose 编排其它服务、或在 Kubernetes 中单实例部署。下文给出镜像选型、一条命令起容器、Compose 一键起栈与一份多文档 K8s 清单；密码与数据卷请按环境自行替换，勿把生产密钥提交进仓库。

一、前置条件

本机已安装 docker，并能使用 docker compose（Compose V2 插件，命令为 docker compose；若仍使用旧版独立程序，则将下文中的 docker compose 换成 docker-compose）。

二、PostgreSQL 镜像选择

1. 官方镜像（推荐）

  • 仓库：postgres（Docker Hub 官方库，由 PostgreSQL / Docker Official Images 维护）。
  • 常用标签：
    • postgres:16：16.x 当前常用大版本。
    • postgres:17 或 postgres:latest：较新线（以 Docker Hub postgres tags 为准）。
  • 生产建议：固定小版本标签（如 postgres:16.6）或记录 digest，避免 latest 漂移导致行为变化。

2. 变体说明

需求 说明
超级用户与库 POSTGRES_USER 为数据库超级用户名（默认 postgres）；POSTGRES_PASSWORD 为其密码；POSTGRES_DB 为首次创建的库名（未设置时默认与 POSTGRES_USER 同名）。
ARM64（Apple Silicon 等） 官方 postgres 多架构镜像一般可直接拉取；若某标签缺架构，换标签或查 Hub OS/ARCH。
极简/定制 社区有 bitnami/postgresql 等，环境变量与数据路径与官方不同，切换镜像时需对照该镜像文档。

3. 编码与本地化

需要固定库编码、排序规则时，可通过 POSTGRES_INITDB_ARGS 传入 initdb 参数（如 --encoding=UTF8 --locale=C），与业务 client_encoding、迁移脚本约定一致。

1Panel（推荐）：在 Linux 宿主机上若希望少手写命令、仍以容器方式跑 PostgreSQL，可先安装 1Panel（开源 Linux 运维面板），在 「应用商店」 中选择 PostgreSQL 一键部署：由面板管理镜像版本、数据持久化、端口与备份等。与下文 docker run / Compose / K8s` 的环境变量、卷路径对齐或排障时，自 # 三 起各节仍可作对照。
