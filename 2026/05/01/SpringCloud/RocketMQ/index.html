Spring Cloud Alibaba 接入 RocketMQ（SCA 2025.1.x 与 Spring Cloud Stream）

发表于 2026-05-01 更新于 2026-05-02 分类于 SpringCloud 本文字数： 840 阅读时长 ≈ 3 分钟

RocketMQ 在 Spring Cloud Alibaba（SCA） 中通过 spring-cloud-starter-stream-rocketmq 绑定 Spring Cloud Stream，与 Spring Boot 4.x / Spring Cloud 2025.1.x 同一套 BOM 管理客户端版本。BOM 选型、Gradle 工程骨架见 Spring Cloud Alibaba 与 Gradle 从零搭建；注册发现可与 Nacos 版本选型与容器化部署 对齐。

与 Spring Cloud Alibaba 的版本关系

项 建议 说明
SCA BOM 2025.1.0.0（及后续 2025.1.0.x） 以 GitHub Releases 为准
RocketMQ Client（BOM 管理） 5.3.1 见 spring-cloud-alibaba-dependencies 中 rocketmq.version
Spring Cloud Stream 随 Spring Cloud 2025.1.x 管理 SCA 2025.1.0.0 起 RocketMQ 模块已适配 Spring Boot 4.0
NameServer / Broker 与客户端 5.3.x 同主版本线 本地验证可用下文 Docker Compose；生产以官方运维手册为准

应用侧不要手写 RocketMQ 客户端补丁号，交给 com.alibaba.cloud:spring-cloud-alibaba-dependencies。

与 Nacos、多环境

  • Topic / 消费组：在 Broker 与运维规范中统一命名；destination 与 group 与 RocketMQ 控制台中的资源一致。
  • NameServer 地址：开发用 127.0.0.1:9876；Kubernetes 内用 Service DNS（如 rmq-namesrv.default.svc.cluster.local:9876）。
  • 若全栈使用 Nacos，SCA 仍按各模块 application.yaml 配置 RocketMQ；注册发现与消息中间件职责分离，勿混为一谈。
