Spring Cloud Alibaba 接入 Seata（SCA 2025.1.x 与 Server 2.5）

发表于 2026-05-01 更新于 2026-05-02 分类于 SpringCloud 本文字数： 988 阅读时长 ≈ 3 分钟

Seata 提供分布式事务（AT / TCC / Saga 等）；在 Spring Cloud Alibaba 中通过 spring-cloud-starter-alibaba-seata 接入。SCA 2025.1.0.0 BOM 将 Seata 客户端对齐到 2.5.0，Server 大版本应与之一致。工程骨架与 BOM 见 Spring Cloud Alibaba 与 Gradle 从零搭建；注册与配置中心常用 Nacos，部署参考 Nacos 版本选型与容器化部署。

与 Spring Cloud Alibaba 的版本关系

项 建议 说明
SCA BOM 2025.1.0.0 Releases
Seata Client（BOM） 2.5.0 spring-cloud-alibaba-dependencies 中 seata.version
Seata Server 2.5.x（与客户端同世代） 镜像示例：seataio/seata-server:2.5.0；发行包见 Seata Releases
业务库（AT） 每库 undo_log InnoDB；脚本见 Seata script/client 下对应数据库
Server 存事务元数据（db） global_table / branch_table / lock_table / distributed_lock 见 Seata script/server/db

官方文档与示例

  • SCA 2025.x Seata 快速开始：https://sca.aliyun.com/docs/2025.x/user-guide/seata/quick-start/
  • Seata 官网：https://seata.io/
  • 多服务示例：https://github.com/alibaba/spring-cloud-alibaba/tree/2025.1.x/spring-cloud-alibaba-examples/seata-example

依赖（Gradle Kotlin DSL）

AT 模式：业务库 undo_log

在参与 AT 分支的每个业务库执行官方 undo_log 建表脚本（引擎 InnoDB）。SCA 快速开始中有示例 DDL；升级 Seata 大版本时请对照发行说明是否调整表结构。

Seata Server 快速启动（本地验证）

1. 单机文件存储（最简单）

适合本机联调：元数据存 Server 本地文件，不配外置库。

说明：镜像标签以 Docker Hub seataio/seata-server 为准；若无对应 patch 标签，可改用同 2.5.x 已发布标签，或直接使用 Seata Releases 中的 seata-server 发行包启动。

  • TC 默认端口 8091；控制台常见 7091（以镜像说明为准）。
  • 客户端 tx-service-group 与 service.vgroupMapping.* 必须与 Server 侧 registry 可见的 cluster 一致（见下文 application.yaml）。

2. db 模式 + Nacos（与官方示例一致）

生产或多人环境：在 MySQL 中导入 Server 侧表结构；Server 使用 store.mode: db；注册与配置使用 Nacos（dataId 如 seataServer.properties、seata.properties 等按运维规范）。步骤与 SQL 汇总见 SCA 快速开始 与 Seata 部署文档。

应用侧最小配置（application.yaml）

以下演示 客户端 指向本机 TC，registry.type: file 且通过 grouplist 指定 TC 地址（与单机 Docker 对应）。生产请改为 Nacos / Etcd 等与 Server 一致的注册、配置方式。

  • tx-service-group：与 Seata Server、Nacos 中 service.vgroupMapping.<your-group>=default 等资源一致。
  • @GlobalTransactional 或 TCC / Saga API 标注在业务入口方法上；RestTemplate / Feign 与 SCA 组合时 XID 传播由 starter 处理（详见官方「对 Spring Cloud 支持点」）。

将 grouplist.default 换成你的 TC 可达地址；若 TC 在 Docker 而应用在宿主机，一般为 127.0.0.1:8091。

与 Nacos 配置中心（官方示例路径）

使用 Nacos 托管 Seata 规则时，常见做法是在 Nacos 创建 seata.properties（或按 Server 2.5 文档拆分多 dataId），并包含 service.vgroupMapping.<应用tx-group>=default 等项；Server 与业务应用均指向同一 Nacos 地址与命名空间。具体 Key 列表可参考 Seata 仓库 script/config-center/config.txt 并结合当前 Server 版本说明裁剪。

联调检查

  1. 日志：发起全局事务时，各参与服务日志中 XID 应一致且随请求变化。
  2. 数据：模拟下游失败后，AT 应回滚业务表与 undo_log 状态符合预期。
  3. 控制台：Server 2.x 控制台可观察全局事务与锁（端口以实际镜像/启动参数为准）。

参考链接

SCA 2025.1.0.0 + Seata 2.5.0 组合下，先完成 undo_log 与 Server 可达地址，再配 tx-service-group / vgroup-mapping，即可在微服务中验证 AT；上生产前请完成 db 模式、高可用 TC 与 Nacos 配置评审。
