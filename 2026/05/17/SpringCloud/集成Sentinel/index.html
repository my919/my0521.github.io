集成Sentinel

发表于 2026-05-17 更新于 2026-05-31 分类于 SpringCloud 本文字数： 978 阅读时长 ≈ 3 分钟

概述

Sentinel 提供流控、熔断、系统保护。本仓库通过 Spring Cloud Alibaba Sentinel 集成；控制台默认 http://192.168.1.22:30012（K8s NodePort，Pod 内端口 8858）。客户端与控制台通信用 8719（可 SENTINEL_TRANSPORT_PORT 覆盖）。

架构



flowchart LR
  App[业务服务 / Gateway]
  Dash[Dashboard :30012]
  App -->|心跳 + 上报| Dash
  Dash -->|推送规则| App
  App -->|Feign 资源名| App

前置条件

项 本仓库 / 建议 说明
SCA BOM 2025.1.0.0
Sentinel Core 1.8.9（BOM + 根 pom.xml sentinel.version） 适配 Boot 4 / Jackson 3
Dashboard 1.8.9 控制台 JAR 或容器 本仓库 NodePort 30012 → 8858
客户端 transport 8719 SENTINEL_TRANSPORT_PORT

Maven 要点

  • spring-cloud-starter-alibaba-sentinel
  • 排除 sentinel-transport-simple-http，改用 sentinel-transport-netty-http（根 pom.xml 已声明 sentinel-transport-netty-http 1.8.9）
  • Gateway 模块额外：spring-cloud-alibaba-sentinel-gateway

配置说明

配置项 / 环境变量 说明 本仓库默认
SENTINEL_ENABLED 总开关 true
SENTINEL_DASHBOARD 控制台地址 192.168.1.22:30012
SENTINEL_TRANSPORT_PORT 客户端监听 8719
SENTINEL_CLIENT_IP 上报 IP（多网卡） 空
feign.sentinel.enabled Feign 纳入 Sentinel true
spring.cloud.sentinel.eager 启动即连控制台 false

规则持久化（可选）

默认规则在内存；生产可通过 spring.cloud.sentinel.datasource 接 Nacos 等（sentinel-datasource-nacos）。本仓库未配置持久化，以控制台临时规则为主。与 集成Nacos.md 同栈时，可将流控规则 DataId 与业务配置分开管理。

与其它组件的关系

  • Gateway：cloud-gateway 使用 Sentinel Gateway 适配，资源名多为路由 ID。
  • Feign：cloud-app 等调用下游时产生独立资源名。
  • Seata / 下单：限流触发 BlockException，与事务回滚无关。

验证

  1. 启动 cloud-order，调用任意接口（如 GET /stock/goods/1 经网关）触发 Sentinel 初始化。
  2. 控制台 机器列表 出现 cloud-order（延迟数十秒属正常）。
  3. 在控制台配置流控规则，压测 POST /order/place 观察是否 Block。

常见问题

Q：控制台看不到客户端？
A：检查 SENTINEL_DASHBOARD 是否为 30012；防火墙放行；客户端是否排除 simple-http 并使用 netty-http；是否已有流量触发 Sentinel。

Q：日志里连 8858 或 wrong port？
A：Nacos 覆盖了 transport；保证 application-sentinel-client.yml 在 import 链最后，dev yml 再写一遍 dashboard。

Q：eager: true 要不要开？
A：本仓库 eager: false，首请求后才注册；调试可改 true 提前连控制台。

Q：Feign 与 Sentinel 资源名？
A：feign.sentinel.enabled=true 时，下游调用会作为独立资源，可在控制台按资源名配规则。

与 Gateway 联用

cloud-gateway 引入 Sentinel Gateway 适配后，可对路由 ID 或自定义 API 分组配置流控。规则持久化可接 Nacos（本仓库默认未配规则 DataSource，规则以控制台临时配置为主）。调试时建议先对 单机直连 cloud-order 验证，再在网关上配置 routeId 级规则。
