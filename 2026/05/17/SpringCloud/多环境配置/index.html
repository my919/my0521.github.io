多环境配置

发表于 2026-05-17 分类于 SpringCloud 本文字数： 565 阅读时长 ≈ 2 分钟

概述

本仓库用 Profile（dev / test / prod）区分环境，用 spring.config.import 分层加载 classpath 与 Nacos 配置。Spring Cloud Alibaba 2025.1.x 已移除 bootstrap，不得在 bootstrap.yml 里连 Nacos，必须在 application-{profile}.yml 中通过 optional:nacos:... 引入（见 SCA 2025 Nacos 进阶）。

架构与加载顺序

原则：application-sentinel-client.yml 在 import 链末尾，用于覆盖 Nacos 里错误的 8858 等；application-dev.yml 末尾可再次写 seata.enabled，覆盖 Nacos 中关闭 Seata 的旧配置。

各模块 import 对照

模块 classpath import Nacos import（dev/test/prod）
cloud-gateway shared, sentinel-client application.yml
cloud-user / cloud-app shared, sentinel-client application.yml
cloud-order / cloud-stock shared, datasource, seata, sentinel-client application.yml, application-datasource.yml, application-seata.yml

cloud-user、cloud-app 不引入 application-seata.yml（无分布式事务参与方）。

环境变量

变量 作用
SPRING_PROFILES_ACTIVE dev / test / prod
NACOS_SERVER_ADDR 注册与配置中心
NACOS_USERNAME / NACOS_PASSWORD 鉴权
MYSQL_* 见 application-datasource.yml
SEATA_ENABLED 全局关 Seata
SENTINEL_ENABLED 全局关 Sentinel

验证

  1. dev 启动 cloud-order，日志无 Nacos import-check 报错。
  2. Nacos 控制台可见 cloud-order 实例。
  3. 修改 Nacos 中 application-datasource.yml 后重启或依赖 refresh 策略验证是否生效。

常见问题

Q：启动报必须配置 spring.config.import nacos？
A：2025.1 强制检查。在对应 profile 的 yml 增加 optional:nacos:application.yml，或按官方说明设置 spring.cloud.nacos.config.import-check.enabled=false（不推荐）。

Q：Nacos 里 Seata 仍是 false，本地 yml 已 true？
A：Nacos 后加载会覆盖。在 application-dev.yml 末尾显式 seata.enabled: true，或更新 Nacos DataId application-seata.yml（模板见 config/nacos-application-seata.yml）。

Q：test 与 prod 和 dev 有何不同？
A：结构相同，仅 application-test.yml / application-prod.yml 中 Nacos 地址、账号可按环境替换；集成测试可用 H2 + seata.enabled=false（见 cloud-order 测试配置）。
